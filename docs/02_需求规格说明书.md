# VideoGuard-E 需求规格说明书（PRD）

**版本：** v0.6 / 2026-10-12  
**文档类型：** 团队需求与验收依据，不是参赛作品报告。  
**第一原则：** 保持一条审核主线、前后端分离、无需训练模型。  
**当前状态说明：** 文中标注“已完成”的功能指原型已进行本地或模拟接口测试；不代表第三方真实模型已联调。

## 1. 产品背景与目标

### 1.0 审核范围

当前规则覆盖十类内容安全风险线索：危险行为诱导、暴力或危险行为画面、个人隐私暴露、营销及资质声称、自伤风险、性内容风险、仇恨与骚扰、诈骗与高风险诱导、受控商品风险、未成年人保护。规则只做线索标注、证据关联和人工复核分流；不直接认定违法、身份、资质真伪或事件真实性。

### 1.1 目标用户
- **短视频创作者/运营者：** 上传拟发布视频，提前查看潜在内容安全风险和需要修改的片段。
- **平台内容审核人员/课程演示评审：** 快速查看风险候选、证据时间和原因，决定是否进一步人工核查。

### 1.2 主要用户任务
> 上传一段合法授权的短视频，在一个页面里得到各类风险的审查状态、能够回放的证据片段、具体修改建议，并下载离线可阅读的HTML报告。

### 1.3 目标不是
- AI直接自动处罚、删帖或进行最终违法认定；
- 提供可替代专业资格核验的身份真假判断；
- 建设完整内容审核中台、账号权限体系、消息队列或云端批量任务平台；
- 训练视频理解大模型或部署GPU服务。

## 3. 两类核心审核需求

### 3.1 重点场景A：危险行为诱导（研究核心）
需要区分：
- `危险行为呈现`：画面中发生或明确描述了危险动作。
- `危险行为诱导`：视频中的语音、字幕或标题鼓励他人尝试相关行为。
- `安全警示或反对模仿`：画面可能仍有风险动作，但传播态度不是鼓励。
- `语义无关`：鼓励话语发生在附近，却不是对那个危险动作的引导。
- `不确定`：模型给不出可靠的关联或无法定位片段。

最低交互要求：每个候选都要展示规则ID、支持证据/反向证据和时间段；不能仅因为出现“危险动作”就断言“鼓励模仿”。

### 3.2 重点场景B：暴力画面与表达语境（研究对照）
需要区分：
- 视频实际呈现疑似暴力/冲突画面的事实线索；
- 是否出自影视、新闻、教学或批评语境；
- 涉及传播风险时是否应进一步人工核查。

**警示或新闻语境不等于“画面不存在”，也不自动成为免责理由。**

## 4. 扩展功能（只做基础演示，不拓宽研究范围）

### 4.1 隐私暴露
- 如果视频文字、画面或声音出现疑似联系方式、证件、详细住址，可以提示风险；
- 可能单一模态就足以形成候选；
- UI、HTML及数据库应尽量脱敏，不能无理由展示完整敏感信息。

### 4.2 营销与职业资质声称
- 区分“自称医生/律师/专家”等可观察内容，与“资质真实还是假的”需要外部核验；
- 提供话术修改与材料核验建议；
- 不能仅凭人物服饰、称呼判断违规。

## 5. 非功能需求与约束

| 维度 | 最小要求 |
| --- | --- |
| 运行环境 | Python 3.11+、FFmpeg中的`ffprobe`、浏览器；不要求GPU |
| 软件结构 | 原生HTML/CSS/JavaScript独立前端，FastAPI单进程后端 |
| 数据库 | SQLite单张`reviews`表；不搭MySQL或消息队列 |
| 上传限制 | ≤6MB，≤180秒，MP4/MOV/WebM；现有代码使用Base64调用Omni |
| API配置 | 只在后端配置阿里云Key和可选TypeSafe Key；不能从浏览器直连收费模型 |
| 单用户条件 | 初版为本地单人演示，绑定127.0.0.1；不宣称支持多用户公网部署 |
| 数据保存 | SQLite保存文件名、SHA256、时长、状态及脱敏审核JSON；不永久保存原视频 |
| 隐私与授权 | 上传前需确认授权；敏感原片或受限内容不可未经许可发送模型服务 |
| 错误与日志 | 模型失败输出ERROR，保存审计记录，前端不得显示为安全 |
| 模型输出 | 必须校验证据ID、时间范围、模态、字段；缺失证据时转人工或报错 |
| 性能与费用 | 记录API耗时与调用成本，实际指标以真API联调结果为准，不编造固定响应秒数 |

## 6. 审核结果的数据含义

必须拆成两个独立维度：

**A. 内容判断（`judgement`）**
- `SUPPORTED`：本次机器观察有支持风险的线索，仍需结合原视频；
- `NOT_SUPPORTED`：在当前已覆盖观察中没有找到支持；**不代表绝对安全**；
- `INSUFFICIENT`：证据不够或关联关系无法确定；
- `CONFLICTED`：同一行为的支持/反向语义存在冲突；
- `UNKNOWN`：模型拒答、处理不完整等导致无法判断。

**B. 处置建议（`disposition`）**
- `FLAG`：提示审核关注；
- `NONE`：本条规则暂无进一步动作；
- `REVIEW`：人工回看；
- `VERIFY_EXTERNAL`：外部核验；
- `RECHECK`：补充观察/重新核查；
- `RETRY`：服务故障后重试。

### 用户体验规则
- 前端显示中文标签；数据保存结构化英文代码，便于评估和测试。
- 不得把`REVIEW`当作“已正确检出”，也不能把模型未发现当作“证明合法”。
- Max只是解释者，不应在解释中新增证据ID、修改PEAD风险判定。

## 7. 关键交互与页面

第一版只需要**一个主页面**：
1. 上传区：本地视频预览、标题输入、素材授权勾选、审核按钮。
2. 结果区：按需展示需要处理的审核项（内容判断 + 处置），并明确本次已评估的十类审核范围。
3. 证据区：按时间列出证据，点击可回看对应视频位置。
4. 修改建议区：展示原因与整改建议；面向审核者不展示内部模型或规则来源。
5. 下载：单文件HTML报告，支持浏览器打印。

**不需要：** 用户注册、审核任务列表、角色权限、消息推送、多级菜单、图表仪表盘、后台管理系统。

## 8. API需求（与v0.6代码对应）

| 方法 | 路径 | 最低行为 |
| --- | --- | --- |
| `GET` | `/api/health` | 返回服务健康状态 |
| `POST` | `/api/reviews` | `multipart/form-data`：video、title、consent |
| `GET` | `/api/reviews/{id}` | 返回SQLite中的审核JSON |
| `GET` | `/api/reviews/{id}/report` | 输出独立HTML审核报告，带下载文件名 |
| `POST` | `/api/demo` | 返回清楚标记的**合成示例** |

前后端通过HTTP JSON通信，静态前端与FastAPI分别启动，不把第三方密钥写进前端。

## 9. 需求验收样例

| 编号 | 测试步骤 | 预期结果 |
| --- | --- | --- |
| AT01 | 上传未授权视频、未勾选授权 | 请求拒绝 |
| AT02 | 上传0字节、非视频、超过6MB文件 | 请求拒绝，界面提示原因 |
| AT03 | 上传坏文件头或无法读取时长的媒体 | 服务返回媒体无效 |
| AT04 | 无阿里API Key时上传真实文件 | 返回失败并保存ERROR，不能输出“安全” |
| AT05 | Omni漏报候选但观察中有危险动作+同事件鼓励语 | PEAD仍扫描并生成相应风险候选 |
| AT06 | 鼓励语指向另一件事情 | 不应仅凭时间接近自动认定同一风险 |
| AT07 | 安全警示与危险动作共存 | 不得简单地把危险动作等同于诱导 |
| AT08 | Max引用不存在的证据ID | 不允许把该建议作为可靠结果呈现 |
| AT09 | Jev无法访问 | 系统标注已降级，不得假装调用成功 |
| AT10 | 完成合成示例审核，点击报告下载 | 浏览器能打开独立HTML且表明“演示数据” |
| AT11 | 报告中包含HTML特殊字符 | 文字被安全转义，不运行脚本 |
| AT12 | 浏览器关闭或刷新后再查历史审核 | 保存的JSON可查询；旧视频因不存原片无法直接重播 |
