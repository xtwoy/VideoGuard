# Markdown → Word 排版说明（给执行转换的同学或工具）

> **用途：** 把 `docs/10_参赛作品报告.md` 排成官方模板格式的 Word/PDF。本文件只讲怎么排、哪些不能改、哪些必须补，不重复报告内容。
> **源文件：** `docs/10_参赛作品报告.md`（唯一正文来源）。
> **官方模板：** `docs/中国研究生网络安全创新大赛作品报告.doc`。

## 一、模板的硬性要求

以下要求来自模板的"填写说明"页与目录页（不是推测）：

| 项 | 要求 |
| --- | --- |
| 纸张 | A4 |
| 字体字号 | **除标题外，宋体、小四号、1.5 倍行距** |
| 说明文字 | 模板自带的"（建议包括：……）"一类说明要删除；**封面填写说明页保留** |
| 结构 | 目录 → 摘要 → 第一章 作品概述 → 第二章 作品设计与实现 → 第三章 作品测试与分析 → 第四章 创新性说明 → 第五章 总结 → 参考文献 |
| 摘要长度 | **不超过 500 字**（当前 Markdown 版为 414 个汉字，转换后请用 Word 字数统计复核） |
| 参考文献 | 按 **GB/T 7714—2015** 著录（源文件已按该格式写好 6 条） |
| 匿名 | **不得出现学校、院系、指导教师、团队成员姓名**；一经发现取消资格 |
| 封面 | 需填"作品名称"与"提交日期"两项 |

> 模板未写明页数上限。**页数限制以赛事通知为准**，转换前请先确认，再决定图片大小与表格取舍。

## 二、Markdown 标题与 Word 样式的对应

源文件的标题层级已经按模板结构组织好，转换时按下表套用样式，不要自行加级别：

| Markdown | 数量 | Word 样式 | 说明 |
| --- | --- | --- | --- |
| `# 视鉴 VideoGuard-E：……` | 1 | 标题（文档标题） | 封面页居中，二号或小二加粗，可自行调整 |
| `# 摘要`、`# 第一章 …` 至 `# 第五章 总结`、`# 参考文献`、`# 附录` | 8 | **标题 1** | 字号可大于小四；建议三号加粗，居中或左对齐均可 |
| `## 1.1 …` 至 `## 3.10 …` | 33 | **标题 2** | 小四加粗，与正文同字号 |
| 其余正文段落 | — | 正文 | 宋体小四，1.5 倍行距，首行缩进 2 字符 |

`## 目录` 一节在 Markdown 里是手写列表，**转换时删掉它，改用 Word 自动目录**（引用 → 目录），转换完成后按 F9 更新页码。

## 四、表格（共 153 行 pipe 表格）

- 全部转成 Word 表格，**首行设为标题行并勾选"在各页顶端重复"**；
- 表格内文字可降到**五号**（模板只约束正文，表格缩小一号更省版面），但需全篇统一；
- 列宽按内容分配，避免"项目/内容"两列表格被平均分栏导致文字折行过多；
- 表格不要跨页断开：属性里取消"允许跨页断行"。

源文件里有 6 个 ``` 围栏代码块，内容是复现命令（`python -m fixtures.truth_table --write` 等）。

- 建议用**等宽字体（Consolas）小五**、浅灰底、不加边框；

## 九、常见转换问题（提前规避）

1. **标题级别丢失**：用 Pandoc 直接转 Word 时，`#` 会映射成"标题 1"、`##` 映射成"标题 2"，但文字编号（1.1、2.10）是手写的，要确认没有被自动编号功能二次编号。
2. **图片按原始像素插入**：8 张图原始宽度约 1600 px，直接插入会超版面，必须按上表设置宽度（约 14–15 cm）。
3. **表格丢失表头重复**：Markdown 没有跨页表头概念，转完必须手动勾选。
4. **中文引号变直引号**：报告里用的是""与''，某些工具会转成 `"` 与 `'`，导出 PDF 前全文查找替换回来。
5. **代码块行内换行**：长命令可能被自动换行截断，检查是否有命令被拆成两行而失效。
