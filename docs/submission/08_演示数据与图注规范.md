# 演示数据与图注规范

> 内部制作规范。用于避免将人工编写的合成场景误写成真实模型识别结果。

## 1. 数据来源必须区分

| 数据类型 | 仓库位置 | 可以证明什么 | 不能证明什么 |
|---|---|---|---|
| 工程回归样例 | backend/fixtures/cases.py 与 fixtures/cases/ | 指定输入下的回归行为与边界条件 | 真实视频的代表性、准确率或泛化能力 |
| 参赛展示场景 | backend/fixtures/showcase.py 与 fixtures/showcase/ | 具体合成故事输入下，系统链路能产生可解释结果 | 模型曾经观看或正确理解对应的真实画面 |
| 前端工作台截图 | docs/assets/demo/ | 某一版本 UI 对指定合成输入的呈现方式 | 真实视频审核效果或最终 UI 已定稿 |
| 论证机制图 | docs/assets/demo/07-argumentation.png 及对应报告 | 独立工程 fixture 下的论证节点、攻击关系与求解解释 | 它就是五个展示案例之一的同次运行轨迹 |

## 2. 推荐图注

- 展示案例报告：图 X. 合成输入下的 VideoGuard-E 审核结果（人工编写场景，非真实视频识别结果）。
- 同动作对照：图 X. 固定危险动作、改变口播语境的合成对照，用于展示系统对证据关系的不同处理。
- 跨事件冲突：图 X. 合成事件中错误关系回答受到事件作用域约束后转入复核的示例。
- 论证机制图：图 X. 独立工程 fixture 下的 PEAD 论证机制示例；非展示场景的同次运行轨迹。
- 时间线：图 X. 合成场景的结构化事实与时间定位，不是视频画面截图。

## 3. 图片取舍原则

优先保留能支撑技术主张的图片，而不是为了数量展示所有页面。第一版 PDF 建议保留：

1. 总体架构图：说明模块边界与数据流。
2. PEAD 论证图：说明支持、反向关系、攻击边和裁决输出。
3. 同动作不同口播的对照图：说明结论取决于证据关系，而不是标签简单相加。
4. 跨事件误关联图：说明事件作用域约束和人工复核路径。
5. 一张完整审核报告截图：说明证据 ID、时间范围、置信度与整改建议如何交付。

隐私整改页面可在版面允许时作为第六张。上传首页、移动端截图和单纯装饰图不是第一优先级；前端改版后再决定是否替换。

## 4. 每张图的最终验收

- 图中场景、结论、证据 ID 和正文叙述一致。
- 在 PDF 的实际显示尺寸下文字可读，图注紧邻图片。
- 清楚标注合成输入、真实 UI 截图或独立工程 fixture，不混淆来源。
- 不出现密钥、个人敏感信息、机器本地路径或无关浏览器界面。
- 不把 PUBLISHABLE 写成“视频整体安全”或“平台保证可发布”。
- 不将合成样例的预期符合数写成真实准确率、召回率或性能提升百分比。

## 5. 禁止使用的表达

- “模型识别出真实视频中的……”——除非该视频确实经过已配置的真实模型链路，且有记录可核查。
- “准确率达到 X%”——当前没有真实视频人工标注评估，不可用合成用例符合预期数代替。
- “十类风险均由 PEAD 论证求解”——当前专项论证求解集中于危险行为诱导，其他策略深度不同。
- “未发现风险，视频安全”——应改为“在当前已观察信息与策略范围内未发现对应线索；不构成整体安全保证”。
