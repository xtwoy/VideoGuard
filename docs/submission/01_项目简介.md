# 视鉴 VideoGuard-E：作品简介

> 工作稿。团队信息、赛道官方措辞及最终版本号请在提交前核对。

## 1. 项目概述

视鉴 VideoGuard-E 是一个面向短视频内容安全场景的辅助审核原型。系统把视频理解得到的事实、问题线索和语义关系分开处理，再由 PEAD（Policy–Evidence–Audit Decision）证据约束决策引擎检查这些信息能否共同支持某个风险判断，最后生成带有证据引用、时间范围、处置建议和不确定性说明的审核报告。

本作品关注的不是简单地让多模态模型输出一个“风险/安全”标签，而是一个更具体的问题：**几条机器观察是否确实指向同一个事件，并且是否足以支持同一个风险结论？**

例如，视频画面出现危险动作，附近又出现一句“试试看”，并不能仅凭时间接近就认定说话者在鼓励模仿。该话语可能针对另一事件，也可能是在警示观众。系统需要检查事件归属、关系核验结果、反向语境和证据完整性；证据冲突或不足时，应提示人工复核，而不是把模型的高置信回答直接当成事实。

## 2. 主要设计

系统采用可替换的上游分析阶段和独立的判断层：

1. 视频上传与基本校验；
2. 视频事实解析；
3. 风险线索定位；
4. 候选事实之间的语义关系核验；
5. PEAD 证据约束、论证求解与规则裁决；
6. 生成审核报告，并由本地工作台和 HTML 报告呈现。

PEAD 的核心流程包括证据作用域规范化、同源证据合并、支持/反向/未决论证构造、攻击关系求解，以及按显式规则输出判断和处置。结论可关联到证据 ID 与时间范围，便于人工回看和核验。

## 3. 作品创新点

### 3.1 将“标签共现”与“证据关联成立”分开

系统不把动作线索和口播线索的同时出现直接视为风险成立，而是检查它们是否属于同一事件、语义关系是否经过核验、是否存在冲突或开放未决。

### 3.2 用可追溯的论证关系解释结论

PEAD 为支持、反向语境和不确定性建立论证节点与攻击关系，使用 grounded 论证语义求解，并把相关证据、规则和处置原因写入结果。这使审核建议不只是一项标签或分数。

### 3.3 将风险强度与证据可信度分开表达

高风险线索不会仅因低置信度而被静默丢弃；报告应同时表达处置建议、证据置信度和需人工核实的具体证据。观察不完整、关系未核验或事件归属冲突时，系统可以转向复核。

### 3.4 将规则配置纳入完整性约束

危险行为诱导的 PEAD 规则集以及十类策略配置都设有完整性校验，防止通过删除既有风险路径或弱化处置下限让风险无声消失。

## 4. 当前验证范围

当前验证以冻结的合成上游输入为基础，执行 PEAD 决策代码和报告校验链路。仓库包含 18 套工程回归样例、5 套专门撰写的展示场景，以及自动化测试、真值表和论证攻防机制报告。

**重要边界：** 当前没有完成真实模型 API 联调，也没有建立真实视频的人工标注测试集，因此不能据此宣称真实视频上的准确率、误报率、召回率或相对性能提升。五套展示场景是合成输入，不是模型从原始视频中实际识别出的结果。

PEAD 的论证求解目前只用于危险行为诱导这一核心研究策略；其余策略的实现深度不同，不能表述为十类风险均经过相同的论证分析。

## 5. 适用定位

本作品用于辅助审核人员整理风险候选、追溯依据和识别需要进一步核查的情况，不替代人工审核，不作违法认定，也不将“当前未发现该类风险”解释为视频整体安全或平台必然允许发布。
