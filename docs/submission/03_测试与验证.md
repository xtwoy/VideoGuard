# 测试与验证报告

## 1. 验证原则

本作品将机制验证、工程回归和真实视频效果评估明确区分。当前完成的是前两类中的一部分；没有真实模型 API 联调，也没有真实视频人工标注集，因此不报告真实视频准确率、误报率、召回率或泛化性能提升。

## 2. 验证项目

| 项目 | 当前证据 | 能支持的结论 | 不能支持的结论 |
|---|---|---|---|
| 后端自动化测试 | GitHub Actions 在基线提交记录 249 项通过 | 已覆盖测试范围内的代码行为符合断言 | 所有输入、所有部署环境均无缺陷 |
| 前端类型检查与构建 | 主分支 CI 成功 | 当前前端可通过所配置的类型检查和构建 | 前端可用性、无障碍或所有浏览器均已验证 |
| PEAD 决策真值表 | 64 组关系回答组合 | 当前枚举输入空间内的决策行为可被系统性检查 | 真实模型输出分布或真实视频识别效果 |
| 论证攻防报告 | 4 类机制场景 | 指定合成输入下，攻击关系与 grounded 标签按规则计算 | 真实上游一定会产生同类错误，或真实环境误报率下降 |
| 同输入对照 | 10 个合成场景 | 指定输入下，无 PEAD 与有 PEAD 的行为差异可复现 | 独立人工标注意义上的准确率提升 |
| 配置完整性探针 | 修改/删除关键规则或策略的反例 | 已测试的配置削弱路径会被拒绝 | 对所有未来配置变化都形式化证明安全 |
| 展示场景 | 5 套人工编写的合成输入 | 可展示 PEAD 和报告链路在这些输入下的运行 | 原始视频已被模型正确解析 |
| 工程回归 fixture | 18 套 | 覆盖若干历史缺陷和策略路径 | 18 套样例具有真实场景代表性或统计独立性 |

## 3. 关键实验说明

### 3.1 64 组关系回答穷举

当前实验对已定义的合成用例枚举四种关系回答值（`encourages_same`、`insufficient`、`unrelated`、`warns_same`）的组合，并检查决策是否可定义、是否确定、是否符合枚举协议以及是否满足指定的保守性性质。

该穷举覆盖的是当前 fixture 所定义的候选对和输入范围，而不是所有可能的视频内容、事件结构或上游模型输出。

### 3.2 同输入对照

同一组冻结输入分别经过不使用 PEAD 的简单映射分支和当前 PEAD 分支。当前报告记录 10 个合成场景中，预先声明的合成处置预期符合数分别为 8/10 和 10/10。

**解释边界：** 这些数字是合成场景的预先声明处置预期符合计数，不是由独立标注人员对真实视频进行评估的准确率。用例并非随机抽样，不能把结果推广到真实视频，也不能把“符合预期”写成真实性能提升百分比。

### 3.3 论证攻防形态

机制报告展示四类构造性场景，包括同事件支持与反向语境冲突、跨事件的错误鼓励关系、跨事件的错误警示关系，以及无攻击的纯支持情形。该报告使用合成 fixture 作为输入，论证构图与求解由真实代码执行。

配图必须标注为“合成输入下的论证机制验证”，不得标为真实视频审核轨迹。

## 4. 复现方式

以下命令应在最终交付提交的干净克隆中重新执行。运行前应按仓库说明安装 Python 依赖。

```bash
cd backend
uv sync --python 3.11
uv run python -m unittest discover -s tests
uv run python -m fixtures.generate --check
uv run python -m fixtures.validate
uv run python -m fixtures.prompt_contract
uv run python -m fixtures.truth_table
uv run python -m fixtures.argumentation_report
uv run python -m fixtures.compare_pead --check
uv run python -m fixtures.argumentation_html --check
```

前端按仓库要求执行：

```bash
cd frontend
npm ci
npm run lint
npm run build
```

定稿时必须记录每条命令的实际结果、执行环境和最终 Git commit；不能仅引用旧提交的 CI 结果来声称新的交付版本已经通过。

## 5. 未验证事项

- 真实模型 API 调用与端到端联调；
- 真实视频样本上的准确率、误报率、召回率和人工一致性；
- 上游事件标识、事实引用、线索归属及反向语境是否在真实回包中稳定成立；
- 不同供应商的兼容性、生产部署、安全加固和可执行打包分发；
- 前端全面可用性评估与真实视频帧对应关系。

这些是当前研究边界，应如实写明，而不是用更多合成测试数字代替。
