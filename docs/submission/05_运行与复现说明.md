# 视鉴 VideoGuard-E：运行与复现说明

本作品面向短视频内容安全辅助审核，包含视频解析、风险线索定位、关系核验、PEAD 证据约束裁决、审核记录保存与报告展示。前端采用 Next.js，后端采用 FastAPI 与 SQLite；PEAD 使用 PyArg 进行论证求解。

## 一、目录

| 路径 | 内容 |
|---|---|
| `frontend/app/` | 上传工作台、审核结果、证据时间轴与整改建议界面 |
| `backend/main.py` | HTTP 接口、视频校验和审核记录 |
| `backend/pipeline.py` | 解析、定位、核验、裁决与报告编排 |
| `backend/src/` | 模型适配器、PEAD、论证图、领域规则与校验 |
| `backend/config/` | 当前风险策略和 PEAD 规则配置 |
| `backend/prompts/` | 各模型阶段的提示词和数据协议 |
| `backend/uv.lock`、`frontend/package-lock.json` | 依赖锁定文件 |
| `THIRD_PARTY.md` | 第三方组件来源与贡献说明 |
| `SOURCE_MANIFEST.json` | 文件清单与 SHA-256 摘要 |

## 二、环境与安装

需要 Python 3.11 或以上、Node.js 20.9 或以上、uv，以及提供 `ffprobe` 的 FFmpeg。建议使用 Python 3.11 与 Node.js 24。

解压后进入 `VideoGuard-E-source`。在 PowerShell 中安装后端：

```powershell
Set-Location backend
uv sync --locked --python 3.11
Copy-Item .env.example .env
```

编辑 `backend/.env`，填写实际服务信息。安装前端：

```powershell
Set-Location frontend
npm ci
Copy-Item .env.example .env.local
npm run build
```

两组命令分别从解压目录的根目录开始执行。安装依赖需要联网，环境文件复制只在首次配置时执行。

## 三、模型服务配置

| 阶段 | 必需配置 |
|---|---|
| 视频解析 | `VIDEO_MODEL_API_KEY`、`VIDEO_MODEL_BASE_URL`、`VIDEO_PARSE_MODEL` |
| 风险线索定位 | `ISSUE_LOCATOR_API_KEY`、`ISSUE_LOCATOR_ENDPOINT`、`ISSUE_LOCATOR_MODEL` |
| 关系核验（可选） | `RELATION_MODEL_API_KEY`、`RELATION_MODEL_ENDPOINT`、`RELATION_MODEL_ID` |
| 模型报告（可选） | `AUDIT_REPORT_MODEL`，使用视频解析服务的连接配置 |

视频解析适配器使用支持视频输入的 OpenAI 兼容接口；问题定位及关系核验适配器按源码约定的 SystemOne 请求协议配置。服务协议、模型标识和返回结构需与对应适配器匹配。

未配置关系服务时，系统保留相应的不确定性与复核路径；未配置报告模型时，使用结构化规则报告。必需服务缺失或调用失败时，本次审核返回错误并保存失败记录。

实际密钥仅保存在本机的后端环境文件中。前端 `NEXT_PUBLIC_API_BASE_URL` 默认是 `http://127.0.0.1:8000`。

## 四、启动与使用

安装完成后，分别运行根目录中的 `start_backend.cmd` 和 `start_frontend.cmd`，两个窗口保持打开。也可手动启动：

```powershell
# 在 backend 目录
.venv/Scripts/python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

```powershell
# 在 frontend 目录
npm run start -- --hostname 127.0.0.1 --port 3000
```

打开 `http://127.0.0.1:3000`，选择获授权的视频并确认授权后提交审核。完成后可查看结论概览、分镜结果、问题与证据、整改与总结，以及独立 HTML 报告。

开发调试时可在前端目录使用 `npm run dev -- --hostname 127.0.0.1 --port 3000` 替代构建服务。

后端按当前实现接收 MP4、MOV、WebM，文件不超过 6 MB，时长不超过 3 分钟。原视频仅用于当前审核请求，不写入 SQLite；浏览器会话中的视频可用于时间定位。数据库首次使用时自动创建在 `backend/data/reviews.db`，可通过 `VIDEOGUARD_DB` 配置。

## 五、接口与检查

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/health` | 后端健康、求解器与规则版本 |
| POST | `/api/reviews` | 上传视频并发起审核 |
| GET | `/api/reviews/{id}` | 读取审核记录 |
| GET | `/api/reviews/{id}/report` | 查看 HTML 报告 |

健康检查：`http://127.0.0.1:8000/api/health`。接口文档：`http://127.0.0.1:8000/docs`。健康接口正常表示应用已启动，视频分析仍需要正确的服务配置。

前端类型检查在 `frontend` 目录执行 `npm run lint`，构建检查执行 `npm run build`。

## 六、常见问题

| 现象 | 检查项 |
|---|---|
| 上传提示无法使用 ffprobe | 确认 `ffprobe -version` 可执行，并重新打开启动终端 |
| 视频校验失败 | 检查容器格式、文件大小、时长与授权确认 |
| 前端连接失败 | 确认后端 8000 端口及前端 API 基地址一致 |
| 模型调用或解析失败 | 核对后端密钥、端点、模型权限、网络及实际返回协议 |
| 前端启动提示缺少构建 | 在前端目录先执行 `npm ci` 和 `npm run build` |

作品以本地单机辅助审核形态运行，结果需结合原片进行人工复核。
