# 参赛 PDF 截图、架构图与技术证据图清单

> **目的：** 每张图都必须支持正文中的一个具体主张。图片不是装饰，也不能把合成结果包装成真实视频识别证据。本文列出的“已有素材”仅表示仓库中存在对应文件，不代表它已通过最终 PDF 尺寸、清晰度和一致性验收。

## 一、配图策略

建议把 PDF 配图分成三类，并在图注中区分：

1. **系统界面截图：** 来自某一版本前端真实渲染的界面，可证明界面如何呈现指定记录；不能单独证明审核结论正确。
2. **机制图/技术图：** 根据实际代码和生成报告绘制或导出的架构、证据图、攻击关系图，可解释系统如何工作；需核对与代码一致。
3. **合成场景结果图：** 人工编写的结构化输入经过正式 PEAD 与报告协议校验后生成的结果。它可以证明这组输入下系统如何运行，但不是模型从真实视频识别出的结果。

建议 PDF 首版使用 4 张核心技术图和 2 张系统界面图。若正文版面不足，优先保留架构、PEAD 机制、同动作对照、跨事件冲突和完整报告；上传首页与移动端截图可以删减。

## 四、每张图的图注应回答什么

一个合格图注至少要回答三件事：

- **图里是什么：** 例如“跨事件误关联的合成输入下，PEAD 的冲突与复核结果”。
- **它能支持什么主张：** 例如“结构性事件指向冲突不会仅因模型回答置信度高就被直接采信”。
- **它不能证明什么：** 例如“该图不证明真实上游模型会发生同样错误，也不代表真实视频识别准确率”。

推荐图注如下：

- **架构图：** 图 1. VideoGuard-E 的处理流水线。上游解析和关系核验通过适配器接入，PEAD 对结构化证据进行约束裁决，最终由报告层输出可追溯的辅助审核结果。
- **论证机制图：** 图 2. 独立工程 fixture 下的 PEAD 论证攻防机制示例。节点标签与攻击关系由真实求解代码对合成输入计算；该图不是五套展示场景的同次运行轨迹。
- **同动作对照：** 图 3. 固定危险动作、改变口播立场的合成对照。该结果用于展示系统对证据关系和反向语境的不同处理，不是视频感知性能评估。
- **跨事件冲突：** 图 4. 构造性跨事件误关联输入下的冲突处置示例。模型关系回答与事件作用域不一致时，系统保留复核而非直接形成强风险提示。
- **整改报告：** 图 5. 合成隐私线索的报告呈现示例。系统将时间范围、证据引用与遮挡建议关联；案例并非真实身份证画面识别结果。
- **时间线：** 图 6. 合成案例的结构化时间定位。图中显示的是解析结果的结构，不是原始视频帧。

## 五、图像制作与排版验收

### 5.1 内容核对

- 图中案例名称、事件 ID、证据 ID、时间范围和处置必须与正文/生成报告一致。
- 机制图的攻击箭头必须从攻击者指向被攻击者，节点颜色/标签必须与实际 grounded 结果一致。
- 不能用截图中的一个总评覆盖正文的局限说明。
- 对照图必须清楚指出被控制的变量和发生变化的变量。
- 若使用新绘制的示意图，应在图注中标注“示意图”，不得伪装成系统真实输出。

### 5.2 清晰度和版面

- 在 PDF 实际显示尺寸下，标题、证据 ID、时间戳和关键结果应可读；不能依赖放大到 200% 才能看清。
- 统一字体、线宽、圆角、留白和颜色语义；同一风险/复核状态在不同图中应保持一致。
- 图片比例不得拉伸；截图裁切时不能切掉必要的状态标签、时间戳或证据说明。
- 图注紧跟图片，不应跨页漂移；图片应在正文首次引用后出现。
- 统一图号、正文引用和目录；不使用“下图”“上图”作为唯一引用方式。

### 5.3 隐私与提交安全

- 检查是否含真实姓名、手机号、身份证号、API Key、机器本地路径、个人账号或无关浏览器界面。
- 不将未获授权的真实视频、个人信息或模型服务回包截图放入参赛 PDF。
- 清理图片元数据或不必要的浏览器标签信息；确认截图来源可说明、可复现。
- 不把 PUBLISHABLE 描述成“视频整体安全”或“平台保证可发布”。

### 5.4 图中文字语言规范

- 图中标题、流程说明、状态解释和图注优先使用中文，不要为了“技术感”把普通说明写成英文。
- 仅保留项目/技术名称、标准文件格式、代码字段、接口路径和固定枚举值；首次出现时应尽量给出中文解释。
- 例如，论证状态可以写为“已接受（IN）”“被击败（OUT）”“未决（UNDECIDED）”；审核状态可以写为“存在冲突（CONFLICTED）/人工复核（REVIEW）”。代码枚举本身不要翻译或改名，以免与实现不一致。
