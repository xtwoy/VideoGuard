# 提交前检查清单

## 1. 团队需要确认的信息

- [ ] 正式作品名称与赛事赛道名称，是否与报名系统一致；
- [ ] 队长、队员、指导教师信息按赛事要求填写；如提交材料要求匿名，评审版中移除学校、学院、导师等身份信息；
- [ ] 每位成员的实际分工和原创贡献由团队确认，不自动推断；
- [ ] 按赛事要求披露 AI 工具名称、版本和使用范围；
- [ ] 核对第三方组件、许可证、引用文献和外部素材授权；
- [ ] 确认赛事规定的 PDF 页数、文件大小、文件命名、可执行程序和声明表模板。

## 2. 技术口径核对

- [ ] 当前代码基线写为实际交付 commit；当前工作稿基线为 `cd33c87ce0dc470c05fb14e77557172d80e9f8a9`，若代码变化则更新。
- [ ] 在最终交付 commit 的干净克隆中重新执行后端测试、fixture 检查、真值表、论证报告、HTML 一致性和前端构建。
- [ ] 记录实际命令与结果，不以旧 CI 结果替代新交付版本的验收。
- [ ] 核对 Prompt 契约检查项数。现有生成报告显示 30 项，其他历史说明曾出现 31 项；重新运行生成器并统一数字后再定稿。
- [ ] 确认 18 套工程回归样例与 5 套展示场景的用途没有混淆。
- [ ] 确认真实模型联调、真实视频准确率/误报率/召回率未验证的限制仍在。
- [ ] 确认只把危险行为诱导描述为当前使用 PEAD 论证求解的专项策略。

## 3. PDF 验收

- [ ] 从 Markdown 生成最终 PDF，并在至少一个桌面 PDF 阅读器中逐页检查。
- [ ] 中文字体嵌入正常，无乱码、方框字、缺字或字体替换。
- [ ] 表格没有被裁切，图片比例正确，图注不与图片分离，页码连续。
- [ ] 目录、章节编号、图号、表号、交叉引用与参考文献一致。
- [ ] PDF 文本可选择/搜索；文件大小和页数符合赛事要求。
- [ ] 删除所有内部 TODO、占位符、草稿说明、工作分支讨论与非提交内容。
- [ ] 按赛事要求完成匿名检查、文件名和作品声明。

## 4. 程序包验收

- [ ] 在干净环境中按说明安装依赖并启动后端/前端。
- [ ] 无 API Key 时，合成场景演示应清楚标识为合成输入；真实调用失败时不得伪装成成功结果。
- [ ] 核对离线演示包资源齐全、内部链接有效、截图与当前报告一致。
- [ ] 附上运行环境、启动命令、演示步骤和已知限制。
- [ ] 不把开发机数据库、真实敏感数据、密钥或临时文件打进提交包。

## 5. 提交后留档

- [ ] 保存最终 PDF、程序包、声明表与提交回执。
- [ ] 记录最终 Git commit、文件 SHA-256 和提交时间。
- [ ] 保存赛事系统确认页或提交成功凭证。
