# 视鉴 VideoGuard-E：设计方案

## 1. 设计目标

目标是建立一条可追溯的短视频辅助审核链路，并将“上游模型观察到了什么”与“这些观察能否支持风险结论”分开。系统不训练视频感知模型；其研究重点在于判断层的证据关联、冲突处理、规则约束和人工复核分流。

## 2. 总体架构

```text
视频上传
  │
  ▼
文件授权与基础校验（文件类型/大小/时长/ffprobe）
  │
  ▼
阶段一：事实解析
  │  分镜、事实、事件、模态覆盖与时间定位
  ▼
阶段二：风险线索定位
  │  线索标签、证据引用、置信度
  ▼
阶段三：关系核验（按候选对执行）
  │  鼓励同一事件 / 警示同一事件 / 无关 / 不足
  ▼
PEAD：证据作用域与论证裁决
  │  规范化 → 构造论证 → grounded 求解 → 规则裁决
  ▼
报告生成与协议校验
  │
  ▼
SQLite 记录 / 工作台 / HTML 审核报告
```

上游各阶段按职责抽象，便于替换服务；PEAD 处理的是上游结构化输入。替换上游并不自动证明新模型遵守协议或提供正确事实，仍需进行真实联调和验证。

## 3. PEAD 的输入与输出

### 输入

- 事件、事实和时间范围；
- 风险线索及其证据引用；
- 关系核验回答及其概率/置信信息；
- 模态覆盖、证据完整性和不确定性；
- 当前版本的风险策略与裁决规则。

### 输出

- 判断：`SUPPORTED`、`NOT_SUPPORTED`、`INSUFFICIENT`、`CONFLICTED` 或 `UNKNOWN`；
- 处置建议：如 `FLAG`、`NONE`、`REVIEW`、`VERIFY_EXTERNAL`、`RECHECK` 或 `RETRY`；
- 原因码、证据 ID、时间范围、置信度和人工核实要求；
- 规则集指纹及可追溯的论证解释。

这些枚举表示系统的辅助判断和建议，不等同于法律结论或平台最终处置。

## 4. 关键机制

### 4.1 事件作用域

动作、话语和反向语境必须通过事件标识、指向关系与时间范围等约束建立联系。缺少可靠标识时，不自动把两条观察视为同一事件。跨事件的错误关联应进入冲突或人工复核路径。

### 4.2 同源证据合并

同一来源的重复描述不能仅因出现多次就成为多份独立佐证。系统依据来源引用和命题对观察进行归并，并记录模型关系判断不是独立的原始视频证据。

### 4.3 可废止论证

系统根据证据和规则构造支持、反向及不确定论证，再建立攻击关系。grounded 求解器计算哪些论证被接受、被击败或仍未决；之后由显式决策规则决定输出，而不是直接把某个标签或分数当作结论。

### 4.4 冲突与未决

结构性冲突可以击败与事实作用域不一致的模型关系回答。未核验候选也不能借助无关回答解除复核门槛。支持证据是否成立与能否给出强风险结论分开处理：证据可以保留，但结论仍要求人工复核。

### 4.5 配置完整性

危险行为诱导的规则集有关键规则和语义不变量检查；十类策略配置另有策略 ID、最低线索集与处置下限校验。配置可以按设计增加更保守的约束，不应通过删除原有路径或降低处置下限来悄然削弱风险识别。

### 4.6 不确定性贯穿报告

时间线完整不等于每个模态都已可靠观察。必需模态未完成、关系候选未覆盖或证据置信度较低时，应在判断和报告中体现不确定性。低置信度的高危线索仍可触发较强处置，但必须绑定具体证据 ID 并说明需要人工核实。

## 5. 策略深度与范围

- **危险行为诱导：** 使用 PEAD 证据图、可废止论证和关系门控，是当前唯一经过专项论证机制验证的策略。
- **暴力或危险行为画面：** 采用动作线索与同事件语境核对。
- **个人隐私暴露：** 使用线索、模态和时间定位过滤。
- **营销及资质声称：** 资质声称需要外部核验，营销线索可转人工复核。
- **其余策略：** 主要通过配置标签映射为判断与处置，未经过同等深度的专项论证实验。

因此，作品覆盖十类策略线索和处置路径，不代表十类都经过相同的 PEAD 论证求解。

## 6. 隐私与系统边界

系统要求上传者确认素材授权，限制视频大小和时长，并对进入持久化结构化结果的部分敏感文本进行脱敏。该脱敏属于基础防护，不等于完整匿名化；自由文本地址、姓名及银行卡号等并非全部覆盖。真实视频经外部模型处理时的传输和合规要求，应按实际部署服务及其数据政策另行评估。

当前原型以本地单机工作台为主，没有账号体系、生产级并发队列或可执行安装包。它适用于技术演示和机制验证，不应描述为已达到生产部署标准。
