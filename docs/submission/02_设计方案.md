# 视鉴 VideoGuard-E：系统设计与 PEAD 技术方案

> **阅读目标：** 说明系统各阶段如何协作、PEAD 如何从结构化观察形成审核建议、规则如何防止常见误配置，以及系统在信息不足时如何降级。本文以当前仓库实现为依据；实现细节应与最终交付版本 复核。

## 1. 设计任务、约束与非目标

### 1.1 设计任务

系统需要把短视频中的机器观察组织成可复核的审核建议。它不仅要发现风险线索，还要明确证据来源、时间范围、事件归属、语义关系、反向语境与信息缺口。核心设计问题是：如何避免“线索同时出现”或“模型高置信回答”未经约束地直接成为风险结论。

### 1.2 工程约束

- 采用本地单机原型形态，优先保证流程可演示、结果可追溯、验证可复现。
- 上游模型服务通过职责适配器接入，不把某一家供应商写入核心决策规则。
- 关键输入和输出使用结构化字段与枚举，减少自由文本对程序控制流的影响。
- 任何上游失败、协议错误、证据无效和资源超限都必须显式记录；不得把失败静默映射为“没有风险”。
- 原始视频不作为二进制写入 SQLite；只保存必要的文件元信息、摘要和脱敏后的结构化结果。
- PEAD 当前专项服务于危险行为诱导；其他策略按各自实现处理，不夸大为统一论证引擎覆盖全部风险。

### 1.3 非目标

本设计不包含模型训练、通用视频 OCR/ASR 系统、平台级在线审核队列、多租户账号体系、生产级部署保证或法律事实认定。系统输出是辅助审核意见，不是执法结论。

## 2. 总体架构与数据流

~~~text
浏览器
  │  上传视频 + 授权确认
  ▼
FastAPI 接口层
  ├─ 文件/类型/大小/授权检查
  ├─ ffprobe 时长读取
  └─ 失败时返回明确错误并记录失败状态
  ▼

  ├─ shots：分镜与时间范围
  ├─ facts：可观察事实与来源 ID
  ├─ events：事件及其指向/立场
  └─ coverage / quality：模态覆盖、可读性与定位质量
  ▼
阶段二：风险线索定位适配器
  ├─ 风险标签
  ├─ 线索与事实引用
  ├─ 候选事件/动作作用域
  └─ 置信度及定位质量
  ▼
阶段三：关系核验适配器（按需）
  └─ encourages_same / warns_same / unrelated / insufficient
  ▼
阶段三点五：PEAD（本作品研究核心）
  ├─ 输入协议与证据引用校验
  ├─ 同源观察规范化及事件隔离
  ├─ 论证节点生成
  ├─ 攻击/防御关系构造
  ├─ PyArg grounded 求解 + NetworkX 解释
  └─ 规则优先级裁决与审计轨迹
  ▼
阶段四：审核报告构建与协议校验
  ├─ finding 与事件级结论
  ├─ 证据/反证状态与整改计划
~~~

## 4. 证据对象与关键字段

PEAD 不直接对原始视频帧进行推理，而是接收上游结构化观察。为避免混淆，文档中的概念含义如下：

- **事实观察（Fact）：** 上游对某一时间范围可观察内容的结构化描述。它是机器报告的观察，不意味着事实已被独立核实。
- **风险线索（Cue）：** 与某项策略有关的候选证据，包含标签、来源引用、时间范围、事件/目标作用域与置信信息。
- **事件（Event）：** 用于隔离不同动作、话语或情境的作用域对象。事件标识缺失时不能自动认定两个线索属于同一事件。
- **候选对（Candidate pair）：** 需要核验关系的两条观察或线索。关系回答应绑定具体候选对，不能被当作对整个视频的全局断言。
- **语义关系（Relation）：** 当前协议使用 encourages_same、warns_same、unrelated、insufficient 等类型化回答。
- **论证节点（Argument）：** 由业务规则从事实与关系中生成的支持、反向或不确定节点；它不是新的独立视频事实。
- **审核问题（Finding）：** 策略层的判断和处置记录，包含原因、证据引用与后续动作。
- **审核报告（Audit report）：** 将事件级判断、证据、观察覆盖、整改计划与整体状态汇总给人工使用。

模型给出的关系回答会被视为需要约束的推断，不作为独立于原始视频的第二份事实证据。报告生成模型也不能覆盖程序已建立的证据来源、反证状态或必须处理的事件。

## 5. 关系约束：为什么“时间接近”还不够

当前关系判据可以形式化为：

**ValidLink(a,s) = ValidTimestamp(a,s) AND SameTarget(a,s) AND SemanticRelation(a,s)**

### 5.1 时间合法性（ValidTimestamp）

时间范围由程序校验，必须处于可用媒体时长范围内，且与引用事实/事件的时间关系满足协议要求。时间合法性只说明时间信息可用，不说明语义关联成立。无效时间或越界引用不得作为有效支持证据。

### 5.2 事件/目标一致性（SameTarget）

程序依据 event_id、referent_key 等结构化作用域字段判断候选是否属于同一事件/目标。事件 ID 与目标标识不是可随意互换的概念：同一人物可以出现在不同事件，同一类动作也可能在不同片段重复发生。字段缺失或冲突时不应默认相同；应保留未决状态或转人工复核。

### 5.3 语义关系（SemanticRelation）

关系核验将候选对归为鼓励同一事件、警示同一事件、无关或信息不足。unrelated 是一个有信息量的否定回答，不能与“没有运行关系服务”混为一谈：前者在满足协议和覆盖条件时可用于否定该候选关联；后者表示缺少核验信息，通常需要保守复核。

三项条件必须同时满足，才可把动作与话语之间的关系作为风险支持路径。关系核验本身仍可能出错，所以其结果还需要接受事件结构、反向语境和论证规则的约束。

## 6. PEAD 核心算法流程

### 6.1 步骤一：证据规范化与同源合并

引擎先把观察按事件和动作作用域归组。同源线索如果引用相同来源并表达相同命题，应归为同一个规范化观察，同时保留原始证据 ID 的别名。这样可以防止同一份证据被重复描述后，被误当作多份独立佐证。

当来源信息缺失时，不通过文本相似度擅自合并。来源合并必须有可追溯依据。关系模型的回答标记为非独立事实证据，不能因为模型重复作答就增加支持数量。

### 6.2 步骤二：生成论证节点

规则根据规范化观察生成三类论证：

- **SUPPORT：** 当前证据支持某个候选风险关联，例如危险动作与针对同一动作的鼓励话语。
- **COUNTER：** 反向语境或结构矛盾削弱该支持，例如同一动作存在明确警示，或模型关系回答与事件指向冲突。
- **UNCERTAINTY：** 证据不足、关系未核验、定位不可靠或覆盖不完整等信息缺口。

每个论证保留稳定 ID、前提证据 ID、来源引用、事件作用域和生成规则 ID。论证节点是对既有证据的逻辑组织，不应在报告中被表述为新观察到的画面事实。

### 6.3 步骤三：建立攻击关系

当两个论证在同一作用域内互相冲突时，规则可建立双向攻击；当结构证据明确否定模型关系回答时，可建立指向该模型论证的攻击边；未核验状态只阻断它自己对应的候选支持，不应跨事件或跨话语击倒无关的独立支持。

构图采用两个阶段：先生成全部论证节点，再依据完整节点集合建立攻击边。否则，攻击边是否存在可能意外取决于规则执行顺序。攻击边按候选/话语作用域限定，避免一条无关的未核验话语连带取消其他已核验支持。

### 6.4 步骤四：grounded 论证接受语义求解

生产路径调用 PyArg 的抽象论证框架与 grounded extension 求解；NetworkX 用于图结构分析、循环/强连通分量与攻击者、防御者解释。求解器给出 IN、OUT 或 UNDECIDED：

- **IN：** 在当前攻击关系下可被 grounded 语义接受；
- **OUT：** 被已接受的攻击论证击败；
- **UNDECIDED：** 现有关系无法给出确定的接受/驳回状态。

Grounded 语义是既有论证框架的方法，本作品不宣称原创该算法。项目贡献是领域证据映射、作用域规则、解释生成和业务裁决。

### 6.5 步骤五：显式规则裁决

grounded 标签不直接等同于最终处置。规则执行器根据支持是否被接受、是否存在冲突、关系是否缺失、观察是否完整和系统是否超限等条件，选择最高优先级的决策规则，输出 judgement、disposition 和 reason_code。所有匹配规则和最终选择应保留在审计轨迹中。

## 7. 判断与处置分离

| 字段 | 取值 | 解释 |
|---|---|---|
| judgement | SUPPORTED | 当前结构化证据满足指定策略的支持条件 |
| judgement | NOT_SUPPORTED | 当前已观察信息不支持该策略结论；不代表视频整体安全 |
| judgement | INSUFFICIENT | 证据或关系不足以作出判断 |
| judgement | CONFLICTED | 支持与反向语境或结构约束发生冲突 |
| judgement | UNKNOWN | 必需观察未完成或无法可靠判断 |
| disposition | FLAG | 提示存在需要重点处理的风险候选 |
| disposition | NONE | 当前策略下暂不采取该项处置，不构成整体安全保证 |
| disposition | REVIEW | 转人工复核 |
| disposition | VERIFY_EXTERNAL | 需要外部核验，例如资质真实性 |
| disposition | RECHECK | 需要补充观察或重新检查 |
| disposition | RETRY | 可重试的上游阶段失败 |

例如，CONFLICTED / REVIEW 的含义不是“系统已经证明模型错了”，而是当前观察中存在不能忽略的冲突，系统不应直接给出强结论，需要人工查看原片。NOT_SUPPORTED / NONE 也只表示当前策略与观察范围内未形成该风险支持，不是全片安全认证。

## 8. 规则配置与防误配置

### 8.1 规则工程化

危险行为诱导规则集包含论证生成规则、处置规则、显式优先级与资源预算。规则条件只能使用预定义布尔事实和受约束的组合操作，不接受任意 Python 表达式或模型生成脚本。加载时使用 Pydantic 进行结构校验，并生成不可变快照和规范化 SHA-256 指纹。

### 8.2 完整性约束

规则集加载时检查关键生成规则、支持裁决规则、失败守卫、处置优先级和语义不变量。例如，若删除支持论证生成路径，系统可能在没有任何警示的情况下也无法生成支持；若删除支持裁决规则，已经接受的支持可能落入默认“暂不支持”。因此，完整性检查不只验证规则 ID 存在，还会用具有已接受支持且没有阻断条件的事实集试跑，要求结果为 SUPPORTED / FLAG。

任何输出 FLAG 的规则必须要求存在已接受支持；模型不可用、证据非法和求解超限等失败守卫必须先于普通决策；冲突、未知关系和覆盖不足的保守分支不能被删除或弱化。已知的配置削弱路径会被拒绝，但这不等于任意未来规则修改都自动正确，修改仍需回归测试与人工审查。

### 8.3 十类策略的配置保护

危险行为诱导的论证规则完整性与十类策略配置完整性是两道不同的检查。策略配置校验要求十个策略 ID 存在、最低风险线索集不能删除、高危处置不低于规定下限，且处置值必须来自允许枚举。不能把这套保护描述成十类都运行了论证求解。

## 9. 不确定性、失败和资源预算

| 情况 | 不应采取的做法 | 当前设计原则 |
|---|---|---|
| 必需模态没有完成观察 | 直接返回 NOT_SUPPORTED / NONE | 返回 UNKNOWN / RECHECK，同时保留已检出的线索 |
| 关系服务未配置或未完成核验 | 把“未核验”当成“无关” | 标记缺失语义关系，按规则转复核 |
| 关系回答与事件指向冲突 | 因置信度高而直接 FLAG | 构造结构冲突论证，保留冲突并转复核 |
| 同事件鼓励与警示并存 | 只保留正向线索 | 生成反向论证，冲突未决时不直接给确定结论 |
| 证据引用无效或时间越界 | 将无效证据继续参与裁决 | 拒绝该证据或触发失败守卫 |
| PyArg 求解失败/资源超限 | 静默回退到旧算法或返回安全 | 产生明确的 INSUFFICIENT / REVIEW 与原因码，不生成虚假的接受证书 |
| 报告与 finding 矛盾 | 让报告模型覆盖程序结论 | 由程序校验 finding、证据、处置和报告总评的一致性 |

资源预算用于限制单事件的论证节点、攻击边和证据移除检查次数。超限时应明确说明未执行哪些检查。预算限制不等于整个视频流水线具备硬实时或恒定内存保证。

## 10. 报告、接口和存储

### 10.1 主要 HTTP 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | /api/health | 返回服务健康与组件状态 |
| POST | /api/reviews | 上传视频并执行审核 |
| GET | /api/reviews/{id} | 查询已保存的审核结果 |
| GET | /api/reviews/{id}/report | 获取自包含 HTML 报告 |
| GET | /api/demo/cases | 列出五个合成展示案例 |
| POST | /api/demo?case={case_id} | 将冻结的合成输入送入正式 PEAD 编排与报告校验链路 |

接口字段和返回码以最终代码为准。/api/demo 是合成数据演示路径，不应在图注或答辩中描述为真实视频识别。

### 10.2 前端工作台

前端按用户工作流组织为上传/授权、结论概览、分镜结果、问题与证据、整改与总结。证据视图保留时间范围和证据 ID；当展示记录没有关联原始视频时，不能假装支持原片回看。界面上的“可发布”（PUBLISHABLE） 或某项策略 NONE 是当前规则和输入下的系统状态，不是对视频整体安全或平台可发布的承诺。

### 10.3 数据与隐私

- 上传前需要授权确认；视频类型、大小和时长受到限制。
- SQLite 保存审核记录、文件名、SHA-256、时长和脱敏后的结构化结果；原始视频二进制不写入数据库。
- 已实现的文本脱敏覆盖手机号、邮箱和 18 位身份证号等格式，但不覆盖所有姓名、自由文本地址、银行卡号、人脸和画面内文字，因此不能称为完整匿名化。
- 跨供应商关系核验应只传递最小化的结构化文本，不传原始音视频；真实部署仍需审查外部服务的数据处理条款。
- 系统默认绑定本机地址，当前没有账号体系、公网部署或生产级并发队列。

## 11. 组件复用与原创边界

| 组件 | 作用 | 归属边界 |
|---|---|---|
| PyArg / python-argumentation 2.0.2 | grounded 论证求解 | 开源组件；求解语义不属于原创 |
| NetworkX 3.6.1 | 图结构、循环、攻击者和防御解释 | 开源组件；通用图算法不属于原创 |
| Pydantic | 规则和结构化对象校验 | 开源组件 |
| FastAPI、SQLite、Next.js、React、Tailwind | Web 服务、存储与 UI | 通用基础设施 |

项目实现的主要工作是：将视频事实映射为论证前提、同源观察归并、事件与动作隔离、关系回答门控、领域规则和配置完整性校验、失败路径与人工复核、证据移除检验、审计轨迹和报告生成。Argdown、OPA 决策日志等是设计参考而非当前运行依赖；SafeWatch 是研究背景参考，不是本项目运行的模型。

## 12. 设计边界总结

PEAD 能约束的是**已经被上游结构化输入表达出来的证据关系**。它不能独立证明上游事实真实，也不能自动补齐完全遗漏的警示。当前设计可以证明某些输入下的裁决行为符合预期，并提供可追溯解释；要评价真实审核质量，还需要真实视频、人工标注、真实 API 回包和独立效果评估。
