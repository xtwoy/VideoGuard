# PEAD 自查与缺陷修复

审查对象是上一份实际交付的 `VideoGuard-PEAD-PyArg-upgrade.zip`。当前修正版为 `pead-pyarg-rules-v2.1`，规则集为 `1.1.0`。

结论：上一版确实存在内部不一致。原有测试通过只覆盖了已有用例，漏掉了配置修改、未定位警示、错误反向关系和报告链上的反例；其中静态判断的“关系已核验”还被旧测试误写成预期。本轮按可执行反例修复并新增回归，没有把旧测试通过等同于无缺陷。

## 发现的问题与处理

| 问题 | 旧行为及影响 | 修复后的约束 |
| --- | --- | --- |
| 事件 ID 与对象指向混用 | `referent_key` 被直接当成事件作用域，同一人物或对象可能导致不同场景混在一起；报告的真实事件 ID 也可能对应不上 | 正式流水线优先使用明确 `event_id`；关系候选、危险诱导、暴力语境和报告采用一致事件隔离。纯旧式内部输入仍可运行，但不能与明确事件 ID 混用 |
| 未定位警示被遗漏 | 同事件警示没有时间戳时不进入候选，已有鼓励证据仍能产生 FLAG，且报告称未发现警示 | 保留为 `UNLOCATED_COUNTER` 不确定论证，阻止该动作自动强提示；警示 ID 仍出现在反向证据中 |
| 模型反向关系缺少作用域检查 | 模型把另一事件的话语判为 `warns_same`，会反驳当前事件的有效支持 | 反向关系也检查事件指向；不适用的模型反证被攻击并排除出有效反证，不能取消另一事件的独立风险 |
| 配置保护只保护了最后一层 | 复核处置规则虽受保护，仍可通过改警示生成条件使其永不触发；也可另加无事实前提的支持规则 | 同时保护警示和信息缺口的生成条件；支持规则必须保留必要事实，失败优先级和原因码必须一致，判断与处置组合必须合法 |
| 论证 ID 及事件命名空间碰撞 | 字符串拼接可能把不同动作／话语对合成同一 ID；已知事件键也可与未知事件的内部键重合 | 论证 ID 使用结构化序列化；事件保留命名空间被转义，缺失指向不会与已知事件合并 |
| 规模检查过晚 | 先构造完整论证和攻击边，再在求解前判断超限，不能真正约束构图规模 | 节点和攻击边在插入时检查预算；超限立即停止本事件构图，标记截断、人工复核，不求解部分图，也不生成支持证书 |
| 关系核验状态失真 | 静态判断未调用模型却标为已核验；仅有部分回答或无效回答也可能被视为全部完成 | 明确区分 NOT_REQUIRED、NOT_CHECKED、PARTIAL、COMPLETE 和 INCOMPLETE；记录候选对数及有效对数；无效结果压成 REVIEW，同源别名的关系结果需全部有效 |
| 报告反证信息可被模型改写 | 正式报告接受模型自填的检查状态；多审核项分组还可能只采用第一项的状态 | 检查状态从领域 finding 重建，按适用审核项合并；报告模型不能把真实发现的警示改成未发现 |
| 人工复核与整改动作不一致 | 复核中的危险诱导仍可能被兜底报告建议直接 REMOVE；存在 FLAG 时安全维度也能被模型标为 PASS | 复核项建议人工核对后再决定编辑，模型的相反结构化动作会被归一；风险维度必须与 finding 保持一致 |
| 汇总风险遮住局部未决事件 | 整体 FLAG 的引用和报告分组可能只涵盖强提示事件，另一事件的 REVIEW 没有相应计划，或被统一建议删除 | 保留所有待处理事件的引用、局部处置和整改计划；报告必须覆盖每个需处理事件，不能转移到无关事件 |
| 证据移除的“保持”表述过宽 | 另一个事件仍触发 FLAG 时，整体处置不变，但局部事件可能已改变；零预算也未明确说明 | 保留全局 `changed` 的同时记录 `scope` 和 `event_changes`；零预算明确标为 DISABLED，不冒充超限或已执行 |
| 事实目录可能被线索 ID 覆盖 | 问题定位的 cue ID 可与事件、事实或分析问题 ID 重名，影响后续证据目录 | 定位投影拒绝这类标识碰撞，不能借复用 ID 改写已有事实目录 |
| 检查工具会修改模型输入 | `build_case()` 在某些测试调用中直接写盘；新引擎还会反向改变生成的报告 Mock 输入 | 检查默认只读；原有报告回包按 SHA-256 冻结，原始错误模型回包保留用于检验正式清洗，不能用新预期替换输入来掩盖缺陷 |

## 修复前后的最小反例

详细机器可读结果保存在 `backend/reports/pead-self-review-validation.json` 的 `six_minimal_counterexamples`。

- 同事件未定位警示：旧版 FLAG、未发现反证；修复后 REVIEW、保留反证引用。
- 另一事件被模型误判为警示：旧版把当前独立风险降为 REVIEW；修复后保留当前 FLAG，并驳回错指的模型反证。
- 修改配置让警示规则不触发：旧版接受配置并产生 FLAG；修复后拒绝该配置。
- 未提供模型关系回答的静态判断：旧版 `relation_checked=true`；修复后为 false，状态 NOT_REQUIRED。
- 带分隔符的动作／话语 ID：旧版合并了不同前提；修复后每个证据对都保留自己的论证。
- 构图超过节点上限：旧版仍构造超出预算的节点；修复后在插入时停止，部分图只能转人工，不能支持风险裁决。

另有回归直接验证：多个真实事件具有相同对象键时仍隔离；一个事件 FLAG、另一个事件 REVIEW 时各自有相应动作；报告模型不能篡改检查状态或把安全风险维度标为通过。

## 第二轮独立静态审计后的修复（2026-10-17）

第二轮审计确认上一轮四项修复已进入代码，并新指出三处。其中一处是真正的代码不一致，一处理论上可复现但样例未触发，一处是能力表述问题。三条均已处理。

| 发现 | 核实 | 处理 |
| --- | --- | --- |
| 正式报告只禁止总分**高于**最低维度，不禁低于 | **成立，且比审计描述更宽**：生成器取的是**全部维度**最小值，校验器用的是**适用维度**（排除 NOT_APPLICABLE）最小值，两者规则本身就不一致 | 抽出 `aggregate_score()` 作为唯一定义：取"已评分维度"（排除 NOT_APPLICABLE）的最低分，全部不适用时退回全部维度最低分。生成器与校验器都调用它，校验器要求**完全相等**（高低两个方向都拒）。新增三项测试：低于最低分被拒、高于最低分被拒、NOT_APPLICABLE 不参与聚合 |
| 事件分组存在两套键序 | **成立**：`_same_referent` 优先 `event_id`，而 `build_event_findings` 内的 `event_key` 只用 `referent_key`。两个不同事件若指向同一语义对象，会被合并成一条事件审计记录 | `event_key` 改为与 `_same_referent` 相同的优先级（event_id → referent_key → 时间三元组）。新增回归：相同 referent_key、不同 event_id 必须分成两条记录，各自只带自己的证据 |
| 十类策略判断深度不一致，能力表述易被误解 | **成立**：只有危险行为诱导走 PEAD 证据图与论证求解；暴力做动作+同事件语境核对；隐私做线索+模态时间过滤；营销做资质外部核验；其余六类是配置标签的直接映射 | 在 README 与参赛作品报告 3.2 增加策略深度表，答辩预案同步改写：明确"覆盖十类线索"不等于"十类都经过证据论证" |

## 第三轮独立静态审计后的修复（2026-10-17）

第三轮审计找到了本项目最严重的一处缺陷：**规则集自我保护没有保护"把支持证据变成风险结论"的路径**。审计同时通过 GitHub Actions 发现 CI 未全绿。六条均已核实并处理。

### P0：风险可以靠改配置消失

| 绕过方式 | 为什么能成立 | 修复 |
| --- | --- | --- |
| 删除 `D_MODEL_SUPPORTED` 与 `D_LOCAL_SUPPORTED` | `integrity()` 只锁死失败守卫、保守裁决与默认规则，没有要求这两条支持裁决存在。删除后已接受的支持证据一路落到 `D_DEFAULT` → `NOT_SUPPORTED / NONE` | 两条规则纳入保护清单（ID + 精确条件 + 结论）；并新增**语义不变量**：加载后用"已接受支持、无阻断条件"的事实集试跑，结果必须是 `SUPPORTED / FLAG`，而不只是检查 ID 存在 |
| 给 `A_LOCAL_PROMOTION` 追加 `relation_review` 条件 | 生成规则只校验"不得丢失原有前提"，追加条件仍满足。收窄后论证根本不会生成，`accepted_support` 变为 false，同样落到默认放行。**仓库里原有的一项测试正是这么做的，并断言结果是 `NONE`** | 两条支持论证生成规则纳入精确条件保护；原测试改为断言配置被拒绝，另加"新增更保守规则仍可生效"的正向测试 |

四条绕过探针（删两条裁决、收紧生成规则、给支持裁决加条件、只删一条）现在**全部被拒绝加载**。

### P1

| 发现 | 处理 |
| --- | --- |
| 线索模态取自事件第一条事实，判决依赖事实排列顺序 | 改为按标签的模态偏好选取（暴力→画面、鼓励→口播、隐私→屏幕文字），多模态无法判断时退回 `metadata` 并标记需人工复核。回归测试：口播在前、画面在后时，violence 线索仍必须是 visual |
| `time_confidence` 由标签概率 `noul ≥ 0.93` 推导 | 拆开两个语义：`time_confidence` 只依据 `coverage.time_localization` 与被引用事实是否带毫秒位置；标签概率只影响是否进入线索与是否需人工复核。回归：概率 0.99 但定位为 APPROXIMATE → `MEDIUM`；事实缺时间 → `UNAVAILABLE` |
| CI 失败：Mock PEAD 对照产物漂移 | 先 diff 再更新：三份产物中 10 个用例与 64 组穷举的**处置结果完全一致**，差异只有输入哈希与事件证据结构，确认来自两次预期改动后才重新生成。今后此类漂移应先看结论差异，再决定是否重新生成 |
| 冻结合成报告的来源标注不清 | `manifest.json` 增加 `audit_report_origin: "synthetic_builder"` 与说明，明确这些阶段四回包由本地确定性生成器产生、冻结只保证字节未被改写；新增测试保证标注不会消失 |

### P2

| 发现 | 处理 |
| --- | --- |
| 同一事件内，某策略的事件记录附带其它策略的线索 | `evidence_ids` 改为与该策略 `supporting_ids`/`counter_ids` 求交集，其余线索单列为 `context_evidence_ids`；`audit.evidence_checked` 相应按直接证据计数。回归测试：暴力与隐私共存于同一事件时，两者各自只列自己的证据 |

### 审计未覆盖、仍未验证

PEAD 规则集的动态绕过已在本机用四个探针实测（非审计方执行），但**真实模型回包下的行为、真实视频准确率、以及冻结回包是否曾来自真实模型**仍未验证。第三轮确认这些回包出自本地兜底生成器而不是模型——这一点此前只是推测，现已作为事实记录在 `manifest.json` 中。

## 第四轮独立静态审计后的修复（2026-10-17）

第四轮专项审计论证构图，找到一处直接威胁核心主张的缺陷；同时定位了远程 CI 一直失败的真因。三条均已处理，并在干净 LF 克隆中验证通过。

### P0：攻击边取决于规则优先级

论证节点按规则优先级依次生成。生成 `REFERENT_CONFLICT` 时，代码只有在该目标节点**已经存在**时才连边：

```
if target in argument_lookup:
    attacks.add((aid, target))
```

默认配置里 `A_MODEL_PROMOTION`（497）先于 `A_REFERENT_CONFLICT`（496）生成，所以边能连上。但 `integrity()` 只固定了规则的种类、作用域与条件，**没有固定相对优先级**。把冲突规则提到 498，冲突论证先生成、目标尚不存在、攻击边被跳过，模型的高置信度错误关系就不会被结构冲突否决——结论从 `CONFLICTED` 变成 `SUPPORTED / FLAG`。

这与"模型错误关系不能覆盖结构性事件冲突"这条核心主张直接冲突，而且不需要删除任何节点或条件。

**修复**：改为两阶段构图——先在本事件内生成全部论证节点，再按完整节点集合解析跨论证攻击边。回归测试把 `A_REFERENT_CONFLICT` 的优先级提到 `A_MODEL_PROMOTION` 之上，断言攻击边集合与裁决结果必须与默认顺序完全一致（实测两种顺序均得到 `CONFLICTED / REVIEW` 且边相同）。

### P1：一条未核验话语会击倒同动作下所有已核验支持

攻击边按"动作作用域"建立，`for unknown in pending: for positive in supports` 让第四条话语的"关系缺失"连带击倒前三条已经核验的支持。三条话语时是 `FLAG`，加一条未获关系回答的话语后变成 `REVIEW`——风险提示没有消失，但独立成立的支持被无关话语取消了。

**修复**：关系缺失类论证只攻击与它**同一话语**产生的支持；跨事件话语本来就不参与本事件判断。同时把"存在开放未决时不得 FLAG"从**攻击边的副作用**改为**显式裁决规则** `D_UNCERTAIN_SUPPORT`（优先级 950，高于支持规则），条件使用新事实 `open_uncertainty`：

- 只统计仍然成立（`IN`）的开放未决，被驳回的模型反证不算——否则"另一事件的警示被正确驳回"也会被误判为未决；
- 只统计本事件相关的话语，跨事件的不确定性不降低本事件结论；
- 该规则纳入规则集保护清单。

这样"支持是否存活"和"能否给出风险结论"变成两件事：支持保留、证据照常列出，结论按规则转人工复核。

### P1：远程 CI 一直失败的真因是换行符

前两轮我把 CI 失败当成"产物忘记重新生成"。实际不是：

- `csv.writer` 默认行终止符是 `\r\n`，仓库 `.gitattributes` 规定 `* text=auto eol=lf`，而 `--check` 比较**原始字节**。本地通过、检出到 CI（LF）必然不一致；
- JSON 产物同理：本地 `pead_rules_v1.json`（364 个 CR）与 `audit_report.py`（902 个 CR）是 CRLF，而它们参与 `source_sha256` 计算，与 CI 检出（LF）的哈希不同。

**修复**：CSV 显式 `lineterminator="\n"`；仓库内文本文件统一为 LF。**验证方式**：在干净 LF 克隆（`git -c core.autocrlf=false clone`）中运行四项一致性检查与全部测试——全部通过，这才是对 CI 的有效模拟；此前"本地全绿"不能作为 CI 证据。

### 仍有效的判断

- 前三轮修复未出现回归（可读性、总分契约、事件分组、支持规则保护均在位）。
- 本轮所有产物重新生成前均先比对：10 个用例与 64 组穷举的处置结果汇总未变，差异只在规则集指纹与决策轨迹（新增规则进入轨迹，属预期）。
- 仍未验证：真实模型回包下的行为、真实视频准确率、以及 PEAD 在大规模输入下的性能。

## 第五轮专项审计后的修复（2026-10-17）

第五轮审计候选对选择与脱敏链路。远程 CI 在本轮首次全绿（`5a77c85`）。五条发现均已核实并处理，其中三条是入口层的证据归属问题。

### 事件证据归属（本轮优先处理）

| 问题 | 机制 | 修复 |
| --- | --- | --- |
| 事件的 `evidence_refs` 只需**一条**与事件重叠 | 上游多填一个别事件的事实 id，就能把另一场景的警示拖进本事件。PEAD 拿到的事实集合已经是错的，事后的事件隔离无法恢复真实归属 | 每条引用都必须与该事件时间重叠；`counter_context_refs` 同规则 |
| 风险线索只校验引用"存在于全视频事实目录" | 线索可借用其它场景的事实，却仍按声明的事件参与同事件判断 | 线索引用必须落在其所声明事件的时间范围内（事件的 `evidence_refs` 是摘要而非穷举，因此按时间判定而非集合包含） |

### 候选对覆盖

旧排序只看时间距离，于是三条更近的跨事件话语可以占满 3 个名额，真正需要核验的同事件关系排在第四位；而 `semantic_check` 仍可报 `COMPLETE`——**被问的都答了 ≠ 该问的都问了**。

- 排序改为"同事件优先，其次按距离"；
- 新增 `eligible / selected / omitted` 三元计数；
- 有未提问的合格候选时，`semantic_check` 记为 `PARTIAL_CANDIDATES`，导出报告显示"关系核验不完整，相关结论需人工复核"。

### 关系回答自相矛盾

`choice` 与 `probabilities` 分属两个字段，此前各自校验、互不比对：`choice=encourages_same`、`confidence=0.99`、但 `unrelated` 概率 0.97 的回答会作为可靠结论进入 PEAD。现要求所选标签必须是概率分布的首要选项，否则记为 `INVALID_RESPONSE` 并标注 `PROBABILITY_CONFLICT`，门控退回人工复核。四类 `choice` 均有反例测试。

### 采集脚本绕过清洗

`fixtures/upstream_capture.py` 此前把**原始**解析回包直接交给问题定位服务，跳过了 `clean_video_parse`；正式路径会把 `context` 裁剪为已知枚举与引用，采集路径则原样外发。现改为：原始回包仍保留用于取证，但第二阶段的调用使用清洗后的对象。回归测试：在原始 `context` 里塞入带姓名、电话、地址的未知字段，断言外发载荷中不存在该字段。

### 脱敏边界

`redact()` 补充了分隔形式手机号（`138-1234-5678`、`138 1234 5678`、`+86 138 1234 5678`）。但银行卡号、姓名、自由文本地址、画面文字仍**不在覆盖范围**——这不是新缺陷，而是模块本来就声明的边界，现已在 README 与模块注释中写明"是基本防护，不是匿名化"。测试同时固定了已知缺口，避免文档与实现悄悄分叉。

### 验证

后端 213 项测试通过（新增 11 项上游边界回归）；fixtures、Mock 对照、攻防页、prompt 契约四项一致性检查通过；干净 LF 克隆中复跑全部检查亦通过。

## 第六轮专项审计后的修复（2026-10-17）

第六轮的核心判断是：十类策略共享的是审核框架，不是一套统一的安全不变量。危险诱导经过五轮加固，其余六类直接线索策略仍只是配置标签映射。五条均已核实并处理。

### P0：六类策略可以用普通 JSON 配置删掉风险识别路径

`load_policies()` 直接读 JSON，没有任何校验。把 `R_SELF_HARM.action_tags` 改成 `[]`，已检出的自伤线索就会落到 `NO_RELEVANT_CUE` → `NOT_SUPPORTED / NONE`；改 `disposition` 也能削弱处置。这和第三轮修掉的 PEAD 规则绕过是同一类问题，只是发生在规则引擎之外。

修复：新增 `src/policy_config.py`，用 Pydantic 校验十类策略：

- 十个策略必须存在且不得改名；未登记的 ID 直接拒绝；
- 每个策略声明的**最低风险线索集**不得被删除——可以加，不能减；
- 高危策略的处置不得弱于下限（自伤/性内容/未成年人保护至少 `FLAG`，骚扰/诈骗/受控商品至少 `REVIEW`）；
- 处置值必须在枚举内。

四项测试覆盖：清空标签被拒、删掉并列标签之一被拒、降级处置被拒、删除策略被拒；**加严仍然允许**。

### P1：全片覆盖被当成每个模态都已观察

`coverage.status = FULL` 只说明时间线完整，不说明口播或字幕读得清。原实现只把总状态传给策略层，某模态 `UNKNOWN` 时仍可能输出 `NOT_SUPPORTED / NONE`——把"无法判断"写成了"未发现"。

修复：`modalities` 随观察结果一起传给策略引擎，每个策略声明必需模态；必需模态不是 `FULL` 时返回 `UNKNOWN / RECHECK`（原因 `INCOMPLETE_OBSERVATION`），已检出的线索照常报出。

这带来一处**预期的行为变化**：`credential_claim` 用例的字幕观察是 `PARTIAL`，于是隐私/诈骗/受控商品三个策略由"未发现"改为"无法判断"。用例的声明式期望已同步更新并注明原因，裁决本身不变。

### P1：开放疑点的复核门槛可被一条无关反向回答解除

`D_UNCERTAIN_SUPPORT` 的条件里用了 `has_counter`，它表示"存在反向论证节点"，**不表示该节点被 grounded 接受**。于是加入一条与风险无关、尚未被接受的反向回答，就能让规则不成立，结论由 `REVIEW` 升级为 `FLAG`。

修复：新增 `accepted_counter` 事实（只统计被接受的反向论证），规则改用该事实。两条回归：三话语场景必须仍是 `REVIEW`；真正的、被接受的反向证据仍应给出冲突结论（不能被新规则吞掉）。

### P1：关系服务存在两套输出契约，检查器却硬编码通过

提示词与 schema 描述的是 `videoguard_relation_check_v1` 的 `decisions` 数组，而适配器实际解析的是 JEV 类型化 `answers`（`choice` / `probabilities` / `noul`）。契约检查器里那一项写的是 `"passed": True`，因此永远不会失败。

修复：以运行时契约唯一化——重写提示词与 schema 为 `answers` 结构，并把检查器改为**真正校验**：schema 必须描述适配器读取的字段、不得残留 `decisions` 数组、真实 `build_request()` 的问题键必须是 `_relation` / `_review`。同时补了反向测试：喂一个旧格式 schema，检查必须报失败。

检查项由 30 项变为 31 项。

### P1：人工复核标记在进入策略层前丢失

定位器在标签概率不足阈值或模态归属不明确时设置 `needs_human_review`，但转换到策略输入时被丢弃。于是 0.81 概率的自伤线索仍按"确定"输出。

修复：该标记随观察结果传递；直接线索策略命中时，finding 记录 `evidence_confidence`（`HIGH`/`LOW`）与 `needs_human_review`。**风险严重度与证据可信度分开表达**：高危线索仍可 `FLAG`（不确定不等于可以放过），但界面与报告明示"线索置信度低，需人工确认"。前端结果区已加该提示。

### 验证

后端 229 项测试通过（新增 15 项：策略配置 6、模态覆盖 3、置信度 2、契约 2、论证门槛 2）；fixtures、Mock 对照、攻防页、prompt 契约（31/31）四项检查通过；前端类型检查与构建通过。

## 第七轮专项审计后的修复（2026-10-17）

第七轮检查数据链路。第一条是**我上一轮修复时引入的断点**，其余三条是"低置信度没有走完全程"。四条均已处理。

### P1：采集脚本传错层级，定位器不调用模型就返回空结果

上一轮把 `locate_issues(parse_raw)` 改成 `locate_issues(parsed)`——但 `clean_video_parse()` 返回的是**外层包装**，`timeline` 在 `observation_detail` 里面。传外层的结果是：`_event_state()` 找不到 timeline → 事件为空 → `build_jev_request()` 不生成任何问题 → `locate_issues()` 直接返回空线索和"没有可供定位的事件证据"，**全程没有发起外部调用**，而脚本仍会正常写出快照文件。

实测对比：传外层包装 → 0 个问题、0 个事件；传 `observation_detail` → 23 个问题、1 个事件。

修复：抽出 `locator_payload(parsed)` 做取数并校验，避免"少一层索引"这种静默失败。三项回归：两种层级的请求可区分、缺 `observation_detail` 直接报错而不是返回空。

### P1：低置信度只在六类策略生效，另外四类仍是 HIGH

`_f()` 的默认值 `evidence_confidence="HIGH"` 意味着"已高置信核实"。六类直接策略显式传了值，暴力/隐私/营销没传，危险诱导则经过论证图后丢失该布尔字段。

修复：取消该默认值（`None`），在 `assess()` 末尾**按每条 finding 的 `supporting_ids` 找到源线索统一计算**。这样十类策略走同一条规则，也让"论证被接受"与"上游线索是否可靠"两件事分开——grounded 的 `IN` 只说明论证成立，不说明线索可信。

回归覆盖四类特殊分支与论证策略，均为 `LOW / True`。

### P1：低置信度没有强制进入正式报告与导出 HTML

字段到了 finding，但没有变成报告的强制契约：兜底报告对"有证据但置信度低"的 `FLAG` 仍写空 `uncertainties`，校验器只检查 FLAG 与总评一致，导出 HTML 也就无从体现。

修复：

- 兜底报告：低置信度 finding 对应的问题必须追加一条**绑定证据 ID** 的核实说明（`该审核项依据的线索置信度不足（证据 E01）…`）；
- 正式校验器：任何 `needs_human_review=True` 的活跃 finding，必须有某条整改问题挂它、且说明里出现它自己的证据 ID——**只出现"人工复核"四个字不算**；
- 导出 HTML 与前端整改页都会显示这条说明（截图已更新）。

三项回归：兜底报告带绑定说明、删掉说明后校验器拒收、导出 HTML 含该说明。

不改处置强度：高危线索仍可 `FLAG`，变的是报告必须承认证据尚待确认。

### P1：结构化 ID 未执行 Schema 的字符限制

解析 Schema 规定 `fact_id`/`event_id` 匹配 `^[A-Za-z][A-Za-z0-9_-]*$`，但清洗器只做了类型转换、截断和非空检查。于是 `event_id = "alice@example.com"` 能通过，并被原样放进发给问题定位服务的 `state.events` 和问题文本——**这些 ID 不会经过 `redact()`**，因为程序默认它们是技术标识。

修复：新增 `_identifier()`，按 Schema 字符集与长度校验 `fact_id`、`event_id`；**用校验而不是截断**。三项回归：邮箱形式的 event_id 被拒、含姓名电话的 fact_id 被拒、正常 ID 照常通过。

### 验证

后端 240 项测试通过（新增 11 项）；fixtures、Mock 对照、攻防页、prompt 契约（31/31）通过；前端类型检查与构建通过；演示截图与演示包已重新生成。

**仍然成立的边界**：原始视频在内容脱敏前就发送给解析服务，这是明确告知用户的架构选择，不是隐蔽绕过；`upstream_capture.py` 保留原始回包用于取证，但快照应按敏感数据管理，Git 忽略规则不等于加密或访问控制。
