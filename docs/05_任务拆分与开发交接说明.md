## 1. 两分钟项目背景

我们选题为**短视频内容安全辅助审核**，面向真人拍摄与AI生成视频，不限未成年人内容。

希望实现：视频上传后，Omni理解视频中的画面、声音和字幕；Jev辅助识别危险动作与鼓励/警示内容的语义关系；**我们自主编写的PEAD规则引擎**检查证据引用和关系、处理分歧和人工复核；Max生成原因与修改建议；前端展示时间位置并导出HTML审核报告。

**团队原创工作：** PEAD证据关联/约束、审核分流、程序实现与实验评估。  
**第三方能力：** 阿里Omni、阿里Max、TypeSafe Jev。  
**名称纠错：** Jev是TypeSafe提供的AI决策模型，PEAD才是团队的Python审核引擎。

```bash
cd VideoGuard-E-v0.6/backend
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

```bash
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

另开终端：

```bash
cd VideoGuard-E-v0.6/frontend

```

打开`http://127.0.0.1:5173`，可以先点击「查看合成示例」，验证上传页面、风险结果、SQLite和HTML报告。**合成示例不是实际视频审核**。

## 3. 已完成与未完成的真实边界

### 已有原型代码
- `frontend/index.html`、`style.css`、`app.js`：原生前端，支持预览/结果/点击时间/报告下载；
- `backend/main.py`：FastAPI接口、上传校验、异常与授权校验；
- `backend/pipeline.py`：审核主线与失败降级；
- `backend/src/pead_engine.py`：自研规则审核；
- `backend/src/jev_model_client.py`：TypeSafe Jev结构化API适配；
- `backend/src/semantic_fusion.py`：Jev与PEAD结果融合；
- `backend/src/aliyun_client.py`：Omni和Max适配；
- `backend/database.py`：SQLite单表；
- `backend/report.py`：可直接打开的HTML报告；
- `backend/tests/test_mvp.py`：21项MVP后端测试；另有`backend/tests/test_event_audit.py` 1项事件级审计测试，合计22项（已在v0.6执行通过）。

### 必须真实补齐
1. **真实Qwen Omni接口联调**：测试一段合法授权、含声音的小型视频，确认JSON输出格式、音视频信息与时间坐标；
2. **Jev接口与中文语义小样本验证**：没有TypeSafe Key或效果差时允许跳过、记录降级；
3. **真实Qwen Max接口联调**：确保原因与整改建议不会自造证据ID；
4. **真实视频证据核验**：对照回看模型所说的动作、语音和时间点，修复虚假定位；
5. **小型公平对照实验**：A/B/C/D按相同输入和风险定义比较质量、复核量和成本；
6. **最终材料审核**：核对官方提交文件及原创技术披露要求（另由团队安排；本次不写参赛作品报告）。

**不能写成已完成：** 云端模型准确率、真实API全链路测试、PEAD的性能提升。

## 7. 最容易犯的五个错误

1. **把Jev叫做自研审核引擎**：错误。TypeSafe Jev是第三方模型；自研叫PEAD。
2. **把API串联叫原创算法**：错误。必须证明证据约束比无约束方法有用。
3. **把Max输出作为真实事实**：错误。只允许引用已检查的证据，且需要人工核实原视频。
4. **把全部样本转人工后宣称零误报**：错误。必须同步报告人工复核率和自动处理覆盖度。
5. **仅凭政策文件就说系统必然合规有效**：错误。政策说明治理背景，不替代技术实测。
