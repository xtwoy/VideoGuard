## 摘要

短视频内容安全的审核难点，不在于"能否识别出危险画面"，而在于**判断若干条机器观察是否真的共同支持同一个风险结论**。直接让多模态大模型输出风险标签，在"动作与鼓励话语时间相近但话题无关""安全科普片段包含危险动作"等情形上容易产生误报，且结论缺乏可追溯的证据链。

本作品提出并实现 **PEAD（Policy–Evidence–Audit Decision）证据约束决策引擎**：以冻结的全模态解析结果为输入，将观察规范化为带事件作用域的原子证据，构造**可废止论证（defeasible argumentation）**，用 grounded 语义求解后按显式优先级规则裁决，最终输出可回溯到具体毫秒时间范围与证据 ID 的审核建议。

系统的技术贡献集中在**证据层**而非感知层：上游解析与语义核验按职责抽象为可替换适配器，PEAD 不依赖任何特定供应商。围绕 PEAD 建立了三层验证：**穷举决策真值表**（64 种关系回答组合，验证全定义/确定性/单调保守）、**论证攻防报告**（4 类攻防形态，验证模型错误回答被结构性约束否决）、**上游契约静态校验**（prompt 要求的字段与枚举是否被校验器接受）。

## 1. 选题背景与问题定义

### 1.1 现实需求

中央网信办于 2026 年 5 月部署规范短视频内容标注，要求平台提供虚构演绎、AI 生成、营销、转载等必选标签；2026 年 9 月"清朗·整治短视频虚假人设乱象"专项行动进一步关注虚构职业资质、AI 仿冒人物、摆拍编造冲突与营销误导。

上述治理要求指向的共同能力是：**对视频内容的真实性、传播语义与风险语境作出可追溯的判断**，而非仅输出一个合规/违规标签。

**【素材来源】** `docs/01`（含官方来源链接）

### 1.2 现有做法的不足

现有多模态大模型已能根据视频与规则输出疑似风险，SafeWatch（ICLR 2025）等工作已提供多类别视频内容安全检测、策略遵循与透明解释。因此**"把视频交给大模型并输出风险标签"本身不构成研究贡献**。

其局限集中在证据层：

1. **标签共现被当作风险成立**：画面出现危险动作、语音出现"试试看"，不足以证明该语音在鼓励模仿该动作；
2. **语境被忽略**：安全科普、新闻报道、影视演绎中的危险画面易被误判；
3. **证据不可追溯**：结论无法回答"由哪几条证据、在什么时间范围、依据哪条规则得出"；
4. **模型错误无法被约束**：模型给出高置信度但错误的语义判断时，系统缺乏独立于模型的否决机制。

**【素材来源】** `docs/01`、`docs/04` 第 1 节

### 1.3 本作品要解决的问题

> **视频中的几条证据是否真的共同支持同一个风险判断？当"动作""说话""字幕"存在矛盾或证据不足时，系统怎样合理地提示、暂缓或核验，而不是凭空作确定性结论？**

这一问题可以通过程序实现约束，并可用针对性难例比较不同方案。

**【素材来源】** `docs/04` 第 1 节

### 1.4 研究范围

| 类别 | 定位 | 说明 |
| --- | --- | --- |
| 危险行为诱导 | **核心研究场景** | 可直接测试"动作与传播语义是否指向同一事件" |
| 暴力或危险行为画面 | **核心对照场景** | 可检验新闻/影视/教育语境是否被区别对待 |
| 个人隐私暴露 | 扩展演示 | 单模态证据即可触发 |
| 营销与职业资质声称 | 扩展演示 | 区分"声称"与"真实性"，需外部核验 |
| 自伤、性内容、仇恨骚扰、诈骗诱导、受控商品、未成年人保护 | 规则覆盖，未做专项实验 | 由同一规则引擎覆盖，详见 3.2 |

**明确不宣称**：全面检测所有违规类型；替代人工审核；判定违法、身份或资质真伪。

**【素材来源】** `docs/01`、`docs/02`、`backend/config/policies_v03.json`

## 2. 系统总体设计

### 2.1 设计原则

- **单一主线**：视频解析 → 问题定位 → 关系核验（按需）→ **PEAD 证据约束** → 审核报告 → SQLite → HTML 报告；
- **职责可替换**：上游阶段按职责命名而非按供应商命名，通过环境变量配置，更换模型不触碰 PEAD；
- **失败不伪装**：任何阶段的失败都显式标记，绝不静默降级为"无风险"；
- **本地单机**：绑定 `127.0.0.1`，无账号体系、无公网部署、无并发队列。

**【素材来源】** `README.md`、`docs/03`

### 2.2 流水线与阶段职责

```
浏览器上传视频
  → FastAPI 校验（授权 / 6MB / 3 分钟 / 容器签名）+ ffprobe 时长
  → 阶段1 事实解析     videoguard_video_parse_v2    分镜 / 事实 / 事件 / 质量 / 内容分析
  → 阶段2 问题定位     videoguard_issue_locator_v1  逐事件逐标签判定线索
  → 阶段3 关系核验     类型化 Choice/Noul 问答        鼓励 / 警示 / 无关 / 不确定
  → 阶段3.5 PEAD 证据约束（本作品核心）
  → 阶段4 审核报告     videoguard_audit_report_v1   九维度评分 + 整改计划
  → SQLite（单表 reviews）→ 前端展示 + 自包含 HTML 报告
```

**【素材来源】** `docs/03`、`backend/pipeline.py`

### 2.3 技术选型

| 组件 | 选型 | 理由 |
| --- | --- | --- |
| 后端 | FastAPI 单进程 | 原型规模无需队列/微服务 |
| 存储 | SQLite 单表 | 本地单机演示，无需多表关系 |
| 前端 | Next.js 16 + React 19 + TypeScript + Tailwind 4 | 类型安全；无外部 CDN 依赖，可离线演示 |
| PEAD 裁决 | 自研规则集 + PyArg（grounded 语义）+ NetworkX | 见第 3 节 |
| 运行环境 | Python 3.11+、Node、FFmpeg（`ffprobe`） | 已从零克隆验证 |

**【素材来源】** `backend/pyproject.toml`、`frontend/package.json`、`README.md`

### 2.4 数据与隐私设计

- 上传视频**不落库**：仅保存文件名、SHA256、时长与脱敏后的结构化结果；
- 文本脱敏：手机号、邮箱、身份证在进入持久化数据前替换；
- 跨供应商传输：关系核验只接收最小化、脱敏的结构化文本，不传原始音视频；
- 授权确认：上传前强制勾选素材授权。

**【素材来源】** `backend/src/redaction.py`、`backend/main.py`、`docs/03`

## 3. 核心技术与创新点：PEAD 证据约束决策

### 3.1 问题形式化

`REPLACE: 若正式报告需要公式排版，此处放入形式化定义（可选）。`

证据约束的关系判据可表述为：

```
ValidLink(a, s) = ValidTimestamp(a, s) AND SameTarget(a, s) AND SemanticRelation(a, s)
```

- `ValidTimestamp`：由 Python 对原视频毫秒时间计算，不由模型生成；
- `SameTarget`：以事件作用域标识（`event_id` / `referent_key`）判定，**缺失时不自动认定相同**；
- `SemanticRelation`：由关系核验服务给出 `encourages_same / warns_same / unrelated / insufficient`。

**【素材来源】** `docs/04` 第 3.3 节

### 3.2 规则工程化

PEAD 的裁决不再由硬编码分支给出，而由**可校验、可版本、可追溯的规则集**驱动：

| 组成 | 规模 | 说明 |
| --- | --- | --- |
| 论证规则 | 14 条 | 生成"支持 / 反向 / 不确定"三类论证节点 |
| 决策规则 | 11 条 | 按显式优先级选出一条裁决 |
| 规则集指纹 | SHA256 | 每次裁决记录所用规则集指纹 |

**规则集自我保护（`RuleSet.integrity()`）**：规则集加载时强制校验以下约束，违反即拒绝加载——

- 生成侧关键规则按 **ID 与精确条件**固定，删除或改写即报错；
- 支持规则不得丢失前提（如本队规则要求含 `same_event` 与推广标签）；
- 任何输出 `FLAG` 的规则必须含 `accepted_support`；
- 失败守卫（模型不可用 / 资源超限 / 证据非法）必须优先于普通决策；
- 保守裁决（指代冲突 / 立场冲突 / 不确定 / 覆盖不足）按条件与结论锁死。

**意义**：修改配置无法绕过安全约束——放宽约束会导致规则集加载失败。

**【素材来源】** `backend/config/pead_rules_v1.json`、`backend/src/pead_rules.py`、`docs/08`

### 3.3 可废止论证与 grounded 求解

**核心转变**：从"打分 / 阈值 / 标签匹配"变为"**构造论证、求解可接受性、按规则裁决**"。

1. **证据规范化**：观察按事件作用域分组，同源线索合并（相同 `source_refs` 与命题视为同一观察），避免同一份证据被重复计为独立佐证；模型判断标记为 `model_is_independent_evidence: False`；
2. **论证构造**：按论证规则生成节点，带极性（SUPPORT / COUNTER / UNCERTAINTY）、前提证据 ID、来源事实引用；
3. **grounded 求解**（PyArg + NetworkX）：得到 `IN` / `OUT` / `UNDECIDED` 标签，并输出逐论证解释（攻击者、被谁击败、防御链、未决攻击者）与循环；
4. **规则裁决**：按优先级选出一条决策规则，输出 judgement / disposition / reason_code。

**不静默降级**：求解失败或超出资源预算时抛出 `ArgumentationLimitError` 并转人工复核，`fallback=False`。

**【素材来源】** `backend/src/evidence_graph.py`、`backend/src/argumentation.py`、`docs/07`、`docs/08`

### 3.4 判定与处置分离

| 维度 | 取值 |
| --- | --- |
| 内容判断 `judgement` | `SUPPORTED` / `NOT_SUPPORTED` / `INSUFFICIENT` / `CONFLICTED` / `UNKNOWN` |
| 处置建议 `disposition` | `FLAG` / `NONE` / `REVIEW` / `VERIFY_EXTERNAL` / `RECHECK` / `RETRY` |

避免将全部视频简化为"合规/违规"二分。

### 3.5 可追溯与可复现

- 每条结论可回答：**哪条规则触发、哪些证据 ID 支持或反驳、发生在什么时间范围、哪些信息未核实、建议人工做什么**；
- 每条 finding 携带**反证 provenance**：是否检查过反证、检查范围、是否发现、是否调用语义核验——"已检查且无"与"未检查"在报告中读起来不同；
- 规则集指纹与引擎版本记录在每次裁决结果中。

**【素材来源】** `backend/src/pead_engine.py`、`backend/src/audit_report.py`、`backend/report.py`

### 3.6 与"直接调用大模型"的区别（作品主张的核心）

`REPLACE: 若正式报告需要配图，此处插入 backend/reports/pead-argumentation.html 的攻防图截图。`

实测四类攻防形态（`python -m fixtures.argumentation_report`）：

| 场景 | 论证与 grounded 标签 | 含义 |
| --- | --- | --- |
| 同事件「鼓励」vs「反向语境」 | `LOCAL_PROMOTION` **OUT**，`COUNTER_CONTEXT` **IN** | 双向攻击下支持论证被击倒 |
| 跨事件：模型断言同一事件 | `MODEL_PROMOTION` **OUT**，`REFERENT_CONFLICT` **IN** | 结构冲突否决模型的自信回答 |
| 跨事件：模型声称警示同源 | `MODEL_COUNTER` **OUT**，`COUNTER_REFERENT_CONFLICT` **IN** | 模型的反向论证自身被否决 |
| 纯支持、无冲突 | 全部 **IN**，攻击 0 条 | 约束不无故压制正常结论 |

**前三个场景中模型的回答均被结构性约束否决或降级，而不是被采信。**

**【素材来源】** `backend/reports/pead-argumentation.md`、`pead-argumentation.html`

## 4. 验证方法与结果

### 4.1 验证策略：冻结上游输入的消融实验

本作品的贡献层是 PEAD，因此实验设计为**冻结上游**：事实解析、问题定位、关系核验使用固定输入快照，PEAD 与报告阶段运行真实代码。

**该设计的合理性**：固定输入、仅变动待研究变量，可消除上游模型随机性对结论的干扰，使差异归因于 PEAD。

**该设计的代价（已声明）**：结论只在"上游满足 PEAD 输入假设"的前提下成立，见第 7 节。

**【素材来源】** `backend/fixtures/README.md`

### 4.2 穷举决策真值表

关系回答只有四种取值，每个场景的组合可穷举，因此不做采样、直接跑完决策函数定义域：

```bash
python -m fixtures.truth_table --write    # → backend/reports/pead-truth-table.md
```

**规模**：7 个含候选对的用例 × 共 **64 种关系回答组合**，每条组合运行两遍。

**验证的性质**（这些性质合成数据无法伪造，因为它们描述"函数在所有输入下如何表现"）：

| 性质 | 含义 |
| --- | --- |
| **全定义** | 每种可达组合都能得出结论，不漏判、不抛异常 |
| **确定性** | 同一输入必然得到同一结论 |
| **符合协议** | 结论始终是文档化的 judgement/disposition 与已知 reason code |
| **单调保守** | 将某回答从 `encourages_same` 弱化，不会使结论变强 |
| **不依赖标注用词** | 同一内容标为 `warning` 或 `education_context` 结论一致 |

**可直接引用的保守性结论**：危险诱导策略有两个候选对时，**只有两者都确认"鼓励同一事件"才输出 FLAG**；任一候选对持异议即转人工复核。

**【素材来源】** `backend/reports/pead-truth-table.md`、`backend/fixtures/truth_table.py`

### 4.5 上游契约静态校验

真实联调最怕的不是模型答得不好，而是 **prompt 要求的字段校验器不接受**——那会让每条真实回包都在解析阶段失败。此类问题可静态查出：

```bash
python -m fixtures.prompt_contract --write   # → backend/reports/prompt-contract.md
```

检查四个阶段的字段存在性、枚举词表与协议自洽。**当前 34 项全部通过**：不存在"prompt 与校验器契约不一致"导致的必然失败。

**【素材来源】** `backend/reports/prompt-contract.md`

## 7. 证据边界与未完成事项

> **本节为本报告最重要的部分，改写时不得放宽口径。**

### 7.1 已验证与未验证

| 状态 | 内容 |
| --- | --- |
| **已验证** | PEAD 决策机制（穷举真值表、攻防形态、单调保守性）；规则集自我保护；工程回归（180 项测试）；从零克隆可运行；prompt 与校验器的契约一致性 |
| **未验证** | 真实模型回包下 PEAD 输入假设是否成立；真实视频上的准确率、误报率、召回率；真实模型调用与端到端联调 |

### 7.2 上游假设与其风险

PEAD 依赖上游四项假设，**本作品尚未用真实模型回包验证**：

| 假设 | 不成立时的后果 |
| --- | --- |
| 事件带可用的指向标识 | PEAD 无法区分"无关"与"未核验"，只能转人工 |
| 线索与事件标识一致 | 事件作用域错乱，可能把其他场景的警示算入本事件 |
| 线索引用的事实真实存在 | 视为不可靠证据，保留人工复核 |
| 解析标记的反向语境进入线索 | 看不到反证，可能把时间接近的鼓励误判为诱导 |

**已为此提供校验工具**（`fixtures.upstream_capture` + `fixtures.upstream_assumptions`），但**本次未执行真实调用**。

**重要说明**：任一项不成立时，PEAD 的行为是**退化为保守复核**，而**不是**编造结论或静默判定为无风险。

### 7.3 明确不宣称

本作品**不宣称**以下任何一项：

- 误报率、召回率或相对基线的性能提升数字；
- 达到比赛获奖水平或生产级审核标准；
- 多模型意见一致等同于视频事实的双重独立验证；
- 系统标记即构成违法认定。

### 7.4 与效果相关的主张边界

本报告中的实验结果**全部来自冻结上游输入的消融实验**。其性质是**机制验证**，而非**性能评估**：

- 可以说明"在给定输入下，PEAD 的决策行为符合设计"；
- 不能说明"PEAD 在真实视频上判断得对"——后者需要真实视频样本与人工标注。
