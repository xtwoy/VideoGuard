# VideoGuard-E 核心技术与实验验证计划

**版本：** v0.6 / 2026-10-12  
**用途：** 解释“自研技术到底是什么”、设计轻量而公平的效果验证。  
**立场：** 本文提出的是**技术假设与验收方案**，不是实验已成功的结论。  
**不输出：** 未经实测的准确率、召回率、性能增益或“首创”声明。

## 1. 为什么不能只做Omni视频审核？

现有视频大模型可以根据视频和规则输出疑似风险，SafeWatch（ICLR 2025）等研究已提供多类别风险检测和解释。

因此我们如果只把视频交给Omni，再让另一个模型写一段审核理由，技术上很容易被质疑是API拼接。

**自研PEAD最值得尝试解决的问题是：**

> **视频中的几条证据是否真的共同支持同一个风险判断？当“动作”“说话”“字幕”存在矛盾或证据不足时，系统怎样合理地提示、暂缓或核验，而不是凭空作确定性结论？**

这个问题可以通过程序实现约束，并用针对性难例比较不同方案。

参考研究：
https://proceedings.iclr.cc/paper_files/paper/2025/hash/beac6bfb7eac3d651307c16ac747df01-Abstract-Conference.html

## 2. 研究对象与范围

### 核心研究场景
- **危险行为诱导：** 对相同危险动作，视频是否存在鼓励、挑战、怂恿他人模仿的传播语义；
- **暴力画面呈现：** 同一行为出现在新闻、影视、体育训练、反暴力教育场景时，判断与处置是否区别对待。

### 扩展示范场景
- **隐私暴露：** 只凭一段画面文字或语音可形成疑似风险，无需强制双模态；
- **营销资质声称：** 可观察到“自称资格”但不能凭视频确认资格真假，作为外部核验例子。

**不要**为了凑项目规模，声称能全面检测所有违规视频类型。

## 3. 候选原创方法：PEAD证据约束决策

`PEAD = Policy–Evidence–Audit Decision`

PEAD是**我们独立编写的Python决策引擎**；Jev是TypeSafe第三方AI模型。二者不是同一个东西。

### 3.1 输入

Omni提供多条观察：

```text
E1: 危险动作/危险行为描述；模态、时间、事件指向
E2: 鼓励或挑战语言；模态、时间、事件指向
E3: 安全警示/否定/引用；模态、时间、事件指向
...
```

单条观察只能表示“模型报告了某个线索”，不等于原视频已核实。

### 3.2 规则1：从全部观察主动扫描

不能只处理Omni主动上报的`candidate_risks`。PEAD应主动遍历当前启用规则：

- 即使`candidate_risks=[]`，只要观察里包含相关动作和鼓励语，仍进入关系判断；
- 若Omni没有观察到关键事实，PEAD不能凭空补救，这一边界必须在报告中说明；
- `coverage != FULL`、模型拒答、时间戳缺失时不允许输出强行确定的“安全”结论。

### 3.3 规则2：组合关系而非标签共现

**关键技术问题：**

视频里出现“危险动作”，语音里出现“试试看”，**不足以单独证明**语音在鼓励模仿那个危险动作。

对每条候选证据对`(a,s)`，判断应同时参考：
- 是否处于相关时间范围；
- 是否明确指向同一行为/话题；
- 该话语是鼓励、警示、引用还是无关；
- 相关反向语境是否针对同一行为，而不是另外一件事。

简化为方法概念：

`ValidLink(a,s) = ValidTimestamp(a,s) AND SameTarget(a,s) AND SemanticRelation(a,s)`

其中：
- `ValidTimestamp`由Python对原视频毫秒时间进行计算；
- `SameTarget`优先参考Omni事件关联键`referent_key`，不可靠时不能自动认定相同；
- `SemanticRelation`可用TypeSafe Jev判断“encourages_same / warns_same / unrelated / insufficient”；
- 本地PEAD负责把结果转化为风险候选、冲突或复核决策。

**必须诚实指出：** Jev读的是Omni抽取的文字，并不能独立检查原视频。两个模型意见一致，只能算增加了文本语义层的分析，**不是视频事实的双重独立验证**。

### 3.4 规则3：不同证据要求不同

| 风险 | 支持条件（候选） | 不能单独确认的事项 |
| --- | --- | --- |
| 危险诱导 | 有相关危险行为/明确描述 + 有指向该行为的鼓励/挑战语义 | 只有画面动作不等于诱导 |
| 暴力画面 | 具有可定位的疑似暴力呈现线索 | 新闻/影视语境不自动消除画面内容 |
| 隐私暴露 | 可定位的个人敏感信息候选（可只来自一类模态） | 未经授权或构成违法泄露不能直接断定 |
| 营销资质 | 可定位的营销表述或资格声称 | 真实资格或承诺真实性要外部核查 |

这个规则设计是为了避免“所有风险必须同时有视频、音频、字幕”这种错误的通用模板。

### 3.5 规则4：内容判断与后续处置分开

Jev认为关联不明确时，PEAD不能把它直接“改成无风险”。

PEAD分别输出：

- `judgement`：SUPPORTED / NOT_SUPPORTED / INSUFFICIENT / CONFLICTED / UNKNOWN；
- `disposition`：FLAG / NONE / REVIEW / VERIFY_EXTERNAL / RECHECK / RETRY。

例如新闻节目展示危险动作，同时主持人警告不要模仿：**危险动作出现**与**鼓励模仿**是两个不同判断。必要时保留人工复核，但明确的正常警示语境也不应一律判为鼓励诱导。

### 3.6 规则5：结果必须有可核查证据

每个风险输出要能回答：
- **哪条规则**触发了？
- **哪几个证据ID**支持/反驳？
- **发生在视频什么时间范围**？
- **哪些信息仍未核实**？
- **建议人工做什么**？

PEAD的强约束可以单元测试，但“模型描述是否真的发生在原片段中”还需要人工核对。

## 4. TypeSafe Jev的职责与技术边界

Jev是第三方**类型化决策模型**，不是本队自研算法，也不是视频模型。

它的合理用途是：
- 输入少量经脱敏的Omni观察摘要；
- 判断候选证据对的鼓励、警示、无关或不确定语义；
- 返回类型化Choice/Noul结果，给PEAD提供辅助信号。

不让Jev做：
- 接收原始视频、音频；
- 凭空生成片段时间戳或人物身份；
- 决定最终违法与否；
- 取代PEAD对证据ID/时间/状态的硬约束。

**阈值说明：** 代码中的0.85是尚待验证的人工复核分流参数，**不表示Jev的准确率为85%**，也不能在没有标注数据前宣称其概率已经校准。

技术参考：https://docs.typesafe.ai/api

## 5. 要验证的三个核心假设

**H1（错误关联控制）**

相比直接让Omni输出风险标签，PEAD对同一事件/话语的关联约束能否减少“时间近但语义无关”的错误风险提示？

**H2（语境判断与人工复核）**

加入Jev和PEAD分歧分流后，能否对正常安全教育、新闻影视语境降低错误强提示，同时不过分依赖人工复核？

**H3（结果可核查与解释）**

有证据ID及真实时间回看链路时，审核人员是否更容易找到支撑结果的片段？Max的整改意见是否确实引用这些可定位证据？

三项假设都要用数据判断。如果没有改善，不编造结论。

## 6. 对照实验：不扩大成复杂研究平台

### 6.1 四组比较（相同风险定义）

| 组别 | 流程 | 想验证什么 |
| --- | --- | --- |
| A | 原始视频 → Omni直接审核 | 最基本的大模型审核水平 |
| B | 原始视频 → Omni结构化观察 → PEAD | 不使用Jev，仅靠团队规则能改善什么 |
| C | 同一Omni结构化观察 → Jev → 简单风险映射 | 第三方语义判断本身能做多少 |
| D | 同一Omni结构化观察 → Jev + PEAD | 组合策略是否有独立价值 |

- B、C、D必须**缓存复用相同的Omni观察**，减少调用费用和随机性。
- A要使用同等详尽的安全类别、正常语境和审核边界说明，避免故意给A较差的Prompt。
- **Max只用于解释与修改建议**，不参与A/B/C/D的风险分类准确率比较；其输出质量应单独评价。

### 6.2 基础测试素材建议

第一轮**工程联调集**：约8～12段合法授权或自行模拟的视频，确认数据能跑通、时间能回看、HTML能下载。

之后争取**探索性评估集**：约24～40段短视频，包含：
- 危险动作 + 明确鼓励；
- 相同或类似动作 + 明确警示；
- 动作与鼓励话语时间靠近但话题无关；
- 新闻/影视/体育训练等合法语境；
- 普通无明显风险视频；
- 隐私与营销的扩展示例；
- 模型描述不清楚、时间定位错误或观察不完整的边界情况。

> 24～40段视频是可行性阶段的小样本建议，不足以声称泛化能力强、达到生产级审核标准或具有统计上的广泛优势。

**素材边界：** 优先自录、演绎模拟、正规授权素材。不抓取或传播真实受害人私密内容；不要将危险违法影像作为随意公开的训练素材。涉及联系方式等请用虚构数据。

### 6.3 人工标注方法
- 最好两位队员独立标注同一段视频的**行为/语义/时间**，有分歧再讨论统一；
- 对“无法仅凭视频判断真假”的项目标为**需外部核验**，不强行二分类；
- 同一原视频的不同剪辑版本作为一个原始场景分组，不拆到不同测试集合；
- 记录标签版本、审核规则版本、Omni/Jev/Max模型ID与调用日期。

### 6.4 核心评价指标

**风险识别：**
- 真正风险样本中被正确提示、被转人工、完全遗漏的数量；
- 正常样本中被错误提示、被转人工、未提示的数量；
- 自动明确判断部分的precision、recall、F1（口径固定后计算）；
- **人工复核率必须单独列出**，不能把所有转人工样本算作分类正确。

**证据质量：**
- 证据引用结构合法率（ID存在、时间合法）；
- 人工核查的证据真实支持率（原片段是否真的支持文字描述）；
- 时间定位偏差（若人工标注了真实起止）。

**用户价值：**
- 修改建议具体性/可执行性；
- 建议是否引用正确的视频证据；
- 人工找到目标片段所需时间（如能安排小规模使用测试）。

**工程开销：**
- 各阶段API调用次数、估算费用、审核总耗时；
- Jev独立调用是否比其增益值得；
- 原始视频大小、失败与降级比例。

### 6.5 拒判和复核统计口径

至少统计：
- `自动强提示数量`
- `自动暂无风险数量`
- `人工复核数量`
- `需外部事实核验数量`
- `模型失败数量`

**不能**因“转人工比例很高，所以自动误报率很低”就宣称审核系统更好。不同方法需要同时比较复核量与风险质量。

## 7. 自动化测试（工程不变量）

当前v0.6工程已包含22项后端本地测试与JavaScript语法检查，主要涉及：
- 未授权上传、非视频、空文件、超过上限；
- ffprobe元信息读取与异常；
- 模型错误时保存ERROR，不冒充安全；
- Omni候选遗漏与可解析证据；
- API流程的模拟回包；
- SQLite存储及HTML报告；
- XSS特殊字符转义；
- 无Jev Key时标注降级；
- Max对证据ID和时间范围进行限制。

后续继续补充或复跑：
- 时间接近但事件不相关；
- 相关警示与无关警示；
- 多个事件、同一视频不同传播态度；
- Jev响应低可信或不符合类型结构；
- 观察覆盖PARTIAL/UNKNOWN与模型拒答；
- Max新增了不存在的证据；
- 裁切后的视频时间戳映射回原片段的准确性（如启用裁切功能）。

## 8. 项目技术答辩时可以怎么说明

**可以说：**
“我们基于成熟全模态模型，研发了一个以风险证据关联约束为核心的辅助审核引擎。它会主动检查结构化观察中的风险线索，并利用类型化语义判断和规则约束处理同一事件的支持、反向与不充分证据，输出可回看的审核建议。我们通过相同视频、相同基础模型的实验观察其误报、漏报和复核成本。”

**暂时不能说：**
- “我们首次提出了多模态视频安全审核”；
- “多个大模型交叉验证就确保事实真实”；
- “Jev的置信度85%代表审核准确率85%”；
- “我们已经降低X%误报”（除非实验完整可复现）；
- “被系统标记的视频违法”。

## 9. 技术研究通过/调整条件

### 通过的最低证据
1. 确实有一批真实或授权模拟视频、人工标注及回放截图/记录；
2. A与B/D对照条件可比；
3. PEAD在至少一类明确的错误关联场景中给出合理修正，且不会造成大量风险漏报；
4. API调用成本、复核负担和失败案例完整披露。

### 需要调整主张的情况
- PEAD几乎只是重复Omni标签，没有修正任何实际错误；
- Jev在中文语境中经常误判关系或API不稳定；
- 系统把绝大多数样本送人工，无法证明效率价值；
- Omni时间戳和观察频繁不可靠，证据链只是表面可追溯。

**这些情况出现时应缩小研究范围、诚实陈述局限；不靠添加页面或扩充审核类别掩盖问题。**
