# 前端美化说明

整理日期：2026-10-17。对应交接任务见 `14_前端梳理与美化交接.md`；本文记录实际改动、设计依据与验证结果。

## 1. 设计方向

产品的真实材料是**时间位置**与**证据编号**：每条观察都锚在 `00:06—00:14`，每条整改都引用 `E01`、`S001:F001`。通用做法会把内容切成等大的卡片；这里内容本身有一根时间轴。

因此这次重做的核心是把**时间轴当作版面的主干**，而不是再加一层卡片装饰。

### 两条硬规则

1. **界面骨架全部单色**：纸、墨、细线承担所有结构信息。
2. **颜色只出现在风险判断上**：屏幕上只要有颜色，就是在说"这里需要看"。

这条规则对审核工具是语义性的：**没有颜色 = 没有需要处理的东西**。

### 设计变量

| 类别 | 值 | 说明 |
| --- | --- | --- |
| 纸色 | `#EFF1EF` | 冷灰绿纸，避开米色/近黑两个模板默认 |
| 表面 | `#FFFFFF` / `#F6F7F5` | 内容面与内嵌面 |
| 墨色 | `#16211F` / `#42524B` / `#6C7C74` | 三级文字，最低字号 12px |
| 细线 | `#D9DFDA` / `#BFC8C2` | 数据分隔用细线，容器用较深一档 |
| 风险 | `#A62A1E` / `#FBEDEB` | 仅用于 FLAG、FAIL、阻断 |
| 待复核 | `#8A5A10` / `#FAF1E1` | 仅用于 REVIEW、WARNING、补充观察 |
| 已通过 | `#2C6647` / `#EAF3ED` | 仅用于 PASS、可发布 |
| 未知 | `#4E5B56` / `#EDF1EF` | 不适用、无法判断 |
| 标题字体 | 宋体系（`Songti SC`/`SimSun`/`Source Han Serif SC`） | 中文文档标题的排字传统；只用于 ≥17px 标题与总评 |
| 正文字体 | 黑体系（`Microsoft YaHei`/`PingFang SC`/`Noto Sans SC`） | 屏幕正文与数据 |
| 时间码 | 黑体 + `tabular-nums` | 需要按列对齐，但**不使用等宽字体** |

字号从原先大量 10–12px 提到：正文 14px、次要 13px、元数据最低 12px。

### 唯一的高光

结果区顶部的**时间轴**：分镜是按真实毫秒比例的色带，证据是带编号的刻度（E01、E02…）。这是整个界面唯一刻意放大的元素，其余部分保持安静。

**不使用**的常见默认：大数字+小标签+渐变的统计卡、每个区块都一样的圆角卡片与投影、每个标题上方的全大写英文眉题、装饰性的 `01 / 02` 序号。

## 2. 针对交接清单的改动

| 优先级 | 原问题 | 处理 |
| --- | --- | --- |
| 高 | 初始预览空框与结果空框占大量空间 | 删除深色空预览框与空结果框；初始态改为**上传 / 演示两栏入口**，两个入口都在首屏 |
| 高 | 有结果后提交栏仍突出 | 结果占满整宽；提交区收为**顶部一条**，按钮"重新提交"展开，默认收起 |
| 高 | 正文 10–12px、禁用后整体变淡 | 字号整体上调；**禁用只改交互**，时间码保持满对比文字（`TimeRef` 在无视频时渲染为 `<span>` 而非半透明按钮） |
| 高 | 整改页全部铺开、动作在很下方 | 整改分组前置；**维度评分改为紧凑行 + `<details>` 按需展开**，并按评分从低到高排序（问题在前）；P0 默认展开，P1/P2 折叠 |
| 中 | 场景下拉难辨差异 | 改为**可见的场景单选列表**（8 项一次看全）+ 选中项说明，演示时一步切换 |
| 中 | 卡片与英文眉题多、层级接近 | 去掉全部英文眉题与装饰序号；层级改用纸色/细线/字号区分 |
| 中 | 连接状态不鲜明 | 三种状态（连接中/已连接/未连接）有文字 + 圆点，失败另有提示 |
| 中 | Mock 页仍显示"点击可回看" | 按有无原视频切换文案；无视频时时间码不可点，并明确说明原因 |
| 中 | 键盘焦点缺失 | 全局统一 `:focus-visible` 描边（2px 墨色 + 2px 偏移），覆盖 link/button/input/summary |
| 中 | 横向溢出与移动端 | 375/390/320 均无页面级横向溢出；标签栏在窄屏占满整行、视图切换落到第二行 |
| 补充 | 场景列表 8 项被容器裁掉半行 | 去掉固定高度，8 项一次显示完整 |
| 补充 | 观察不完整时 10 条完全相同的行 | 相同 judgement/disposition/reason 的发现**分组**，每个类别仍以标签完整列出 |
| 补充 | 事件审计直接显示 `R_DANGER_PROMOTION:EVT_EDU` | 只显示事件部分（`事件 EVT_EDU`），策略名已在左侧 |
| 补充 | 整改分组标题与视频摘要重复 | 内容相同时不重复渲染 |

## 3. 刻意没有做的事

- **没有加拖放之外的推断**：界面写"拖入视频"就实现了真实的 `dragover`/`drop` 处理，不写未实现的能力。
- **没有加进度百分比**：后端没有阶段进度 API，处理中只显示"正在审核"与禁用态。
- **没有伪造缩略图**：分镜列表只有结构信息与事实数量，不配假的视频帧。
- **没有把 Mock 说成真实分析**：DEMO 记录固定显示"合成场景"标记与"未关联原视频"，并保留"冻结上游输入 → PEAD 证据裁决 → 报告校验"的说明。
- **没有把"需复核"改成"安全通过"**：`NOT_SUPPORTED / NONE` 仍标注"这表示没有支持证据，不等于内容绝对安全"。

## 4. 代码结构

| 文件 | 作用 |
| --- | --- |
| `app/page.tsx` | 页面外壳：深色页眉、两栏入口、结果条、状态提示、页脚 |
| `app/components/video-result-workspace.tsx` | 结果面板：媒体条、粘性标签栏、结构/报告视图切换 |
| `app/components/time-rail.tsx` | 时间轴：分镜色带、证据刻度、比例尺 |
| `app/components/result-tabs.tsx` | 四个标签页内容 + 发现分组 |
| `app/components/ui.tsx` | 基础件：Pill / Tag / SectionHeading / TimeRef / TimeRangeList / 空态与限制说明 |
| `app/lib/types.ts` | 后端返回类型（与 API 契约一一对应） |
| `app/lib/labels.ts` | 文案表、时间格式化、tone 判定（**颜色只在这里决定**） |
| `app/globals.css` | 设计变量（Tailwind 4 `@theme`）、焦点样式、`tnum` 与 `measure` 工具类、减少动效 |

未新增任何依赖。图标仍用已有的 `lucide-react`，字体全部使用本机字体，页面不请求外部字体、CDN 或远程图片。

## 5. 验证

| 项 | 结果 |
| --- | --- |
| TypeScript | `npm run lint`（即 `tsc --noEmit`）通过 |
| 生产构建 | `npm run build` 通过 |
| 截图 | `python -X utf8 backend/fixtures/capture_demo.py` 生成 10 张（8 桌面 + 2 移动端），断言页面已加载对应内容 |
| 窄屏 | 390 / 360 / 320 三种宽度检查，无页面级横向溢出 |
| 状态覆盖 | 初始、结论概览、冲突证据、整改长页、观察不完整、无风险线索、分镜、移动端 |

**关于窄屏截图的说明**：Chrome headless 的 `--window-size` 有最小宽度限制，直接开 390 窗口并不会得到 390 CSS 像素的视口，媒体查询不生效。因此移动端截图通过**固定宽度 iframe** 承载页面获得真实视口；该限制写在 `capture_demo.py` 的 `screenshot_narrow` 注释里。

## 6. 已知限制

- 结果仍为单页四标签，未做多页路由；刷新通过 `?review=` / `?tab=` / `?view=` 保持，与交接要求一致。
- 维度子项展开使用原生 `<details>`，不做跨标签记忆。
- 无原视频时时间轴刻度不可点，这是数据限制而非样式问题。
- 导出报告（`backend/report.py`）与攻防页（`argumentation_html.py`）本轮未改，仍是既有样式。
