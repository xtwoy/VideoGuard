# 演示场景与截图说明

整理日期：2026-10-17（第七轮验收后重做）。演示场景**不再复用工程回归用的 18 套 fixture**，而是使用 5 套专门撰写的展示案例（`backend/fixtures/showcase.py`）：每套都先把视频故事、分镜、可见事实与口播写清楚，再据此生成结构化输入，最后运行正式的 `_run_models` 编排（PEAD、PyArg 求解、关系门控、报告校验）。

两套数据的分工：

| | 工程回归数据 | 参赛展示数据 |
| --- | --- | --- |
| 位置 | `backend/fixtures/cases.py` + `fixtures/cases/` | `backend/fixtures/showcase.py` + `fixtures/showcase/` |
| 数量 | 18 套 | 5 套 |
| 用途 | 单元测试、规则冲突、历史缺陷复现 | 演示与参赛截图 |
| 允许的特征 | 模板化、刻意构造错误、不自然的输入 | 具体、自洽、可核对的画面与口播 |
| 阶段四报告 | 历史冻结回包（旧评分协议，会被当前校验器拒绝并走兜底） | 按案例撰写，**通过当前协议校验** |

每条展示案例的 `case.json` 里有 `report_origin: "authored_synthetic"` 与声明的期望结论，演示测试会据此断言行为没有漂移。

## 打开方式

- 交互工作台：启动服务后访问 `http://127.0.0.1:5173`，在“演示场景”选择案例，点击“运行合成场景演示”。无需选择视频或填写模型密钥。
- 离线演示包：打开 `backend/reports/demo-showcase/index.html`，查看 5 份报告、10 张截图和完整攻防页面。整个目录可以复制到其他电脑。
- 报告截图：`docs/assets/demo/`；核心对照、跨事件冲突、隐私整改等图已组织进 `docs/10_参赛作品报告.md`。**暂无与五套合成案例对应的真实视频帧**，文字分镜仅能说明设定事实，不能充当识别效果证据。
- 原始输出与来源：`backend/reports/demo-showcase/records.json` 保存本次 HTTP 返回记录，`manifest.json` 保存场景、截图来源 URL 与 SHA-256。每条结果的 `meta.fixture_sha256` 记录所用输入文件摘要。

页面截图由 Chrome 无头命令行真实渲染，使用生产前端和 HTTP API，无 WebSocket、无浏览器调试端口。Mock 场景未关联原视频，回看按钮禁用；截图不证明真实视频识别或播放链路已经验证。

## 五个展示场景

| 场景 | 故事 | 讲解重点 |
| --- | --- | --- |
| 天台跨楼动作 + 明确鼓励模仿 | 十二层天台，男子翻越护栏跳过楼间两米空隙，随后说“你们也试试，胆大一点就行” | 画面动作与口播鼓励构成同一事件内的诱导，输出 `FLAG` |
| 同一跨楼动作 + 明确劝阻模仿 | 画面事实完全相同，只把口播换成“千万别学我，这里没有任何防护” | **危险行为诱导策略** `NOT_SUPPORTED/NONE`，不是跨楼动作安全认证；总评 `PUBLISHABLE` 不代替人工核验平台其他规范 |
| 跨事件误关联 | 厨房男子跳过燃烧灶眼；镜头切到户外骑行，骑手说“这个动作我练了三个月，别模仿” | 关系模型把两句判成同一事件，被事件与指代约束否决，转人工复核 |
| 手机屏幕展示身份证照片 | 开箱视频里手机屏幕对着镜头，相册是身份证正面；14 秒后才说“后面会打个码” | 屏幕文字模态的证据、时间定位与遮挡整改 |
| 宠物日常（干净负例） | 柯基追球、睡觉，口播只说“今天给大家看看我家狗子” | 没有线索时不把“未发现”说成合规保证 |

建议三分钟演示顺序：危险诱导结论概览 → 同一动作的劝阻对照 → 跨事件误关联的问题与证据 → 隐私整改建议 → 攻防图 → 离线 HTML 报告。

## 复现（PowerShell，分别使用三个终端）

后端使用单独的演示数据库，避免混入原有审核记录。在 `backend` 目录运行：

```powershell
$env:VIDEOGUARD_DB = Join-Path (Get-Location) 'data/demo-capture/demo.db'
.venv/Scripts/python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000 --ws none
```

在 `frontend` 目录运行生产前端；不要为这套演示使用带热更新连接的开发服务器：

```powershell
npm run build
npm run start -- --hostname 127.0.0.1 --port 5173
```

在 `backend/reports` 目录启动报告服务，供攻防页与移动端截图使用：

```powershell
..\.venv\Scripts\python.exe -m http.server 8765 --bind 127.0.0.1
```

最后在 `backend` 目录重新截图并生成离线演示包：

```powershell
.venv\Scripts\python.exe -X utf8 fixtures/capture_demo.py
```

展示案例本身可重新生成（写入 `fixtures/showcase/`）：

```powershell
.venv\Scripts\python.exe -m fixtures.showcase_build
```

## 这批复核修正了什么

本轮之前的截图用的是工程 fixture 里的场景，存在三个问题，这轮一并处理：

1. **报告来源是兜底生成器**。历史冻结的阶段四回包还是旧评分协议（9 个维度、含已退役的电商维度），当前校验器必然拒绝，于是 8 个场景全部落到 `FALLBACK_INVALID_OUTPUT`，文案来自统一模板。现在改为按案例撰写、并通过协议校验的报告，`meta.audit_report` 为 `DEMO_SYNTHETIC`。
2. **风险标签先于事实**。旧数据先决定要得到哪个 `FLAG`，再补一条能触发的标签；现在先写清画面与环境，风险解释放在问题定位与论证阶段。
3. **文档数字过期**。测试数量、截图数量与实际不一致，已按当前状态更新。

## 验证状态

- 后端 249 项测试通过，其中演示测试覆盖：5 个场景的期望结论、报告来源必须为 `DEMO_SYNTHETIC`（而不是兜底）、记录保存、报告导出、非法场景参数拒绝。
