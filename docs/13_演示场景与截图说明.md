## 打开方式

- 正式工作台：访问 `http://127.0.0.1:3000/`，上传真实视频并确认授权；首页没有合成场景入口。
- 结果设计预览：开发服务运行时访问 `http://127.0.0.1:3000/design-preview`。选择冻结样例，切换“结论概览 / 分镜结果 / 问题与证据 / 整改与总结”。不调用模型；页面明确标注为合成数据设计预览，生产环境不可用。
- 离线演示包：打开 `backend/reports/demo-showcase/index.html`，查看 5 份报告、10 张截图和完整攻防页面。整个目录可以复制到其他电脑。
- 报告截图：`docs/assets/demo/`；核心对照、跨事件冲突、隐私整改等图已组织进 `docs/10_参赛作品报告.md`。右侧场景图和左侧整改卡已使用对应配图；这些图与文字分镜均不能充当案例的真实识别效果证据。
- 原始输出与来源：`backend/reports/demo-showcase/records.json` 保存沿用的冻结返回记录，本轮未改写；`manifest.json` 保存场景、截图来源 URL 与 SHA-256。每条结果的 `meta.fixture_sha256` 记录所用输入文件摘要。
- 攻防图数据：`backend/reports/pead-argumentation.json` 保存本轮实际计算的四个工程场景、原始论证编号、攻击边、标签与裁决轨迹。HTML 页显示该 JSON 的 SHA-256；离线包保留同一份数据。`#figure` 是便于截图的聚焦视图，完整页可展开其余三个场景与原始记录。

页面截图由 Chrome 无头命令行渲染，正式上传页和独立开发预览均通过 HTTP 加载；未使用浏览器远程调试协议。01 展示未选择视频、未提交审核的正式表单。结果预览沿用冻结合成记录，未关联原片，证据回看保持禁用；场景配图不与证据时间绑定。上述截图不证明真实视频识别链路已验证。

## 五个展示场景

| 场景 | 故事 | 讲解重点 |
| --- | --- | --- |
| 天台跨楼动作 + 明确鼓励模仿 | 十二层天台，男子翻越护栏跳过楼间两米空隙，随后说“你们也试试，胆大一点就行” | 画面动作与口播鼓励构成同一事件内的诱导，输出 `FLAG` |
| 同一跨楼动作 + 明确劝阻模仿 | 画面事实完全相同，只把口播换成“千万别学我，这里没有任何防护” | **危险行为诱导策略** `NOT_SUPPORTED/NONE`，不是跨楼动作安全认证；总评 `PUBLISHABLE` 不代替人工核验平台其他规范 |
| 跨事件误关联 | 厨房男子跳过燃烧灶眼；镜头切到户外骑行，骑手说“这个动作我练了三个月，别模仿” | 关系模型把两句判成同一事件，被事件与指代约束否决，转人工复核 |
| 手机屏幕展示身份证照片 | 开箱视频里手机屏幕对着镜头，相册是身份证正面；14 秒后才说“后面会打个码” | 屏幕文字模态的证据、时间定位与遮挡整改 |
| 宠物日常（干净负例） | 柯基追球、睡觉，口播只说“今天给大家看看我家狗子” | 没有线索时不把“未发现”说成合规保证 |

建议三分钟演示顺序：危险诱导结论概览 → 同一动作的劝阻对照 → 跨事件误关联的问题与证据 → 隐私整改建议 → 攻防图 → 离线 HTML 报告。

展示 02 与 06 的 A/B 对照时，紧邻图片注明“**两组动作画面相同，变化的是后续口播**”，分别列出鼓励与劝阻原句，并解释同事件的支持线索和反向语境如何对应两种结论；不向配图添加字幕，也不修改冻结输入。主稿图 4 已将口播原句放在两列截图上方、PEAD 判断依据放在下方。B 的结论只针对危险行为诱导策略，不表示该动作安全。

## 重新截图（PowerShell）

在 `frontend` 目录启动开发预览：

```powershell
npm run dev -- --hostname 127.0.0.1 --port 3000
```

在另一个终端的 `backend` 目录执行：

```powershell
.venv/Scripts/python.exe -m fixtures.capture_design_preview
```

此命令渲染正式上传页与开发预览，并单独重新求解工程攻防样例、更新 07；不调用外部模型、不写入审核数据库，也不修改 `records.json`。旧 `capture_demo.py` 面向已移除的首页演示流程，不用于当前正式页面。

配图路径及来源配置位于 `frontend/public/case-images/manifest.json`，四张已选图片位于同目录。后续换图时更新对应的 `src` 和 `source`，再运行截图命令；不需要视频、FFmpeg 或外部图片服务。截图清单同时记录所用图片的 SHA-256。未配的宠物对照图显示明确占位，不请求不存在的图片文件。

只重做攻防图时，在 `backend` 目录执行下列命令，无需启动前端或后端服务；截图脚本会临时启动仅监听本机的静态 HTTP 服务，截完即关闭：

```powershell
.venv/Scripts/python.exe -m fixtures.capture_design_preview --argumentation-only
```

该命令更新工程 HTML、论证 JSON、两份 `07-argumentation.png`、离线索引及来源清单。图节点、箭头、标签和最终裁决均读取程序输出，只调整布局与中文说明。

若需重建原始展示数据，应单独使用 `fixtures.showcase_build` 及原有工程验证流程；该操作与界面截图更新分别记录。

## 这批复核修正了什么

本轮之前的截图用的是工程 fixture 里的场景，存在三个问题，这轮一并处理：

1. **报告来源是兜底生成器**。历史冻结的阶段四回包还是旧评分协议（9 个维度、含已退役的电商维度），当前校验器必然拒绝，于是 8 个场景全部落到 `FALLBACK_INVALID_OUTPUT`，文案来自统一模板。现在改为按案例撰写、并通过协议校验的报告，`meta.audit_report` 为 `DEMO_SYNTHETIC`。
2. **风险标签先于事实**。旧数据先决定要得到哪个 `FLAG`，再补一条能触发的标签；现在先写清画面与环境，风险解释放在问题定位与论证阶段。
3. **文档数字过期**。测试数量、截图数量与实际不一致，已按当前状态更新。
