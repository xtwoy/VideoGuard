# 视鉴 VideoGuard-E：现场演示脚本与讲解词

> **建议时长：** 8—10 分钟。本文同时供答辩人排练和现场操作者使用。五套参赛展示案例是人工编写的合成输入；如未配置真实模型 API，必须明确说这是合成场景进入正式 PEAD 与报告校验链路的演示，不是现场识别真实视频。

## 一、演示目的与成功标准

演示的目的不是展示“系统有很多页面”，而是用一条清楚的技术主线证明三个点：

1. 同一危险动作，口播立场变化后，系统对“危险行为诱导”这一策略的判断可以不同；
2. 当模型把不同事件错误关联，或同一事件的警示与模型回答冲突时，PEAD 会约束直接结论并保留复核；
3. 系统能够把结论连接到结构化证据、时间范围、原因码和整改建议，而不是只给出一个标签。

一次合格的演示至少应展示：系统架构、同动作不同口播对照、跨事件冲突、证据/整改报告、论证机制图和实验边界。若时间不足，应优先保留机制对照和限制说明，不要只展示首页。

## 二、演示前准备

### 2.1 运行条件

- 后端已启动，健康接口可访问。
- 前端已启动，浏览器可正常访问本地工作台。
- 已确认合成展示场景能够运行，并且报告可保存、可导出。
- 预先打开五套案例与论证机制 HTML 页面，避免现场临时寻找文件。
- 如使用真实模型服务，必须提前确认密钥、网络、额度和获授权测试素材；如果未确认，不在演示中临时尝试真实调用。

### 2.2 建议准备的窗口

1. VideoGuard-E 前端工作台；
2. 结构化时间线或问题与证据标签页；
3. 独立的 PEAD 论证机制 HTML；
4. 可选：同输入对照报告和真值表报告；
5. 备用的本地截图，以防现场显示环境异常。

备用截图只能用于说明界面和机制，不能冒充正在运行的实时结果。

## 三、8—10 分钟演示流程

### 0:00—1:00｜提出问题

**操作：** 打开作品首页或架构图，不急着运行案例。

**讲解词：**

“我们的研究不是重新训练一个视频模型，而是研究多模态审核结果如何形成。画面里有危险动作、附近有一句鼓励性话语，并不自动说明这句话是在鼓励观众模仿该动作。两条观察可能指向不同事件，也可能存在警示语境。我们把证据关联和冲突裁决独立出来，避免只根据标签共现或模型高置信回答直接作结论。”

**需要讲清：**
- 上游负责输出结构化观察；
- PEAD 负责约束这些观察之间的关系；
- 系统输出辅助建议，最终仍由人工审核。

### 1:00—2:00｜讲解总体架构

**操作：** 展示架构图，依次指出上传校验、事实解析、线索定位、关系核验、PEAD、报告和 SQLite。

**讲解词：**

“流程按职责分层。前面阶段给出事实、线索和候选关系；PEAD 不直接看原始视频，而是处理结构化输入。这样可以替换上游服务，但替换服务后仍需验证它是否提供正确字段、事件标识和证据引用。PEAD 不能替上游补出完全没有报告的事实。”

**过渡句：**

“接下来固定画面动作，只改变口播立场，看系统为什么不能只做简单标签累加。”

### 2:00—4:00｜同一危险动作、不同口播立场

**操作：**
1. 打开天台危险动作与鼓励模仿案例；
2. 展示结论概览和问题/证据；
3. 打开动作相同、口播改为明确劝阻的对照案例；
4. 对照证据关系与策略处置。

**案例 A：** 合成事实描述为男子翻越高处护栏并跨越楼间空隙，随后口播“你们也试试，胆大一点就行”。在该合成输入中，动作和鼓励话语被定义为同一事件，关系回答为鼓励同一事件，危险行为诱导策略输出 SUPPORTED / FLAG。

**案例 B：** 保持动作描述不变，将口播改为“千万别学我，这里没有任何防护”。在该合成输入中，反向语境参与判断，危险行为诱导策略输出 NOT_SUPPORTED / NONE 或相应复核状态，以当前生成报告为准。

**讲解词：**

“对照变量是口播立场，而不是危险动作本身。案例 B 的策略结果只表示当前输入没有形成危险行为诱导的支持；它不代表跨楼动作安全，也不代表其他平台规范允许发布。两个案例都是人工编写的结构化输入，PEAD 和报告协议校验是真实代码执行，但并非模型从真实视频中识别出的效果实验。”

**注意：** 如果当前实际结果与预期不同，以界面和生成报告为准，暂停演示并记录差异，不要临时修改文案把结果说成预期。

### 4:00—6:00｜跨事件错误关联

**操作：** 打开跨事件冲突案例，展示两个事件的事实和关系回答。

**合成输入：** 厨房动作和户外骑行分别属于不同事件；冻结输入人为设置一个错误的关系回答，把两条线索判为鼓励同一事件。

**讲解词：**

“这里故意给系统一个错误的高置信关系回答。PEAD 不把置信度当成事实，而是检查事件作用域。如果两条证据来自不同事件，模型回答就不能直接建立有效的支持关系。系统输出冲突与人工复核，而不是把错误关联直接升级为强风险结论。”

**必须强调：** 这是构造性机制测试，不代表真实上游模型已经发生同样错误，也不证明系统能纠正未被上游报告的错误。

### 6:00—7:15｜证据追溯与整改建议

**操作：** 打开问题与证据、分镜时间线和整改与总结。

**讲解词：**

“每个 finding 都应能回答：引用了哪条证据、证据对应什么时间、为什么触发该处置、还缺少什么信息、人工下一步需要核实什么。系统还要区分‘已经检查但未发现’和‘没有足够信息判断’。例如，观察覆盖不完整时，不应因为没有线索就当作安全。”

**可展示内容：**
- 证据 ID 和时间范围；
- 支持与反向证据；
- 观察覆盖与置信信息；
- 整改建议及对应证据；
- HTML 报告导出。

如果展示的是合成记录，原片回看按钮可能禁用，应解释该记录没有关联原始视频，而不是声称回看链路已通过真实素材验证。

### 7:15—8:15｜论证机制图

**操作：** 打开 backend/reports/pead-argumentation.html 或对应截图。

**讲解词：**

“图中的节点代表根据规则构造的论证，箭头代表攻击关系。PyArg 计算 grounded 标签，NetworkX 用于补充图结构与攻击/防御解释，之后由项目规则决定最终处置。这里的标准论证语义和图算法来自开源组件；本项目工作是视频证据映射、事件隔离、领域规则和报告解释。”

**图注边界：** 该页面来自独立工程 fixture 的论证机制测试，不是前面五套展示案例之一的同次运行轨迹。

### 8:15—9:15｜验证结果与限制

**操作：** 展示同输入对照报告或真值表摘要。

**讲解词：**

“我们在冻结的合成输入上穷举 64 种关系回答组合，并对 10 个合成场景比较无 PEAD 和有 PEAD 分支。前者有 8/10 个场景符合预先写明的合成处置预期，后者为 10/10。这个数字不是视频准确率，也不是随机样本上的性能提升。它说明在这些构造性场景中，PEAD 的决策行为符合预先定义的机制预期。真实模型联调和真实视频人工标注评估仍是后续工作。”

### 9:15—10:00｜总结

**讲解词：**

“VideoGuard-E 的贡献是把证据来源、事件作用域、关系核验、反向语境和不确定性显式放进决策过程，使结构性冲突可以被检查、解释并转交人工核查。当前我们验证的是机制行为与工程可复现性，而不是声称真实视频审核已经达到某个准确率。”

## 四、现场异常时的处理

| 异常 | 处理方式 | 不应说的话 |
|---|---|---|
| 后端无法启动 | 使用提前验证过的本地环境；若仍失败，展示已生成报告并说明本次运行异常 | “系统已实时分析成功” |
| 外部模型 API 无密钥/超时 | 切换到合成场景演示，明确标注合成输入 | “这是模型实时识别的结果” |
| 页面加载慢 | 先展示离线机制 HTML，再回到报告截图 | “性能已经满足生产要求” |
| 某案例输出与预期不符 | 记录输入、版本和输出，停止把它当作成功例子 | 临时修改预期或隐藏冲突 |
| 回看按钮不可用 | 说明合成展示记录没有原始视频关联 | “原片逐帧回看已经验证” |

## 五、常见追问的简短回答

**问：你们的创新是 grounded 算法吗？**  
答：不是。Grounded 论证语义和图算法是已有方法。我们的工作是将视频事实、事件作用域、同源证据、关系回答、反向语境和业务处置映射到可检查的论证与报告链路。

**问：为什么不直接让大模型输出最终风险标签？**  
答：因为模型关系回答可能与事件指向或警示语境冲突。PEAD 让这些冲突成为显式约束，并保留可追溯的复核理由。

**问：真实视频上的准确率是多少？**  
答：目前没有完成真实视频人工标注评估，因此不报告准确率、误报率或召回率。现有实验验证的是冻结输入下的机制行为。

**问：十类风险是不是都使用 PEAD？**  
答：不是。危险行为诱导是当前唯一使用论证求解并经过专项机制验证的策略；其他策略的判断深度不同。

**问：系统能否证明视频违法？**  
答：不能。系统输出是辅助审核线索，违法与否、资质真假及平台最终处置需要人工或外部权威核验。
