# 完整研发仓库：工程验证与实验复现（内部）

本文件不提交，适用于包含实验工具的完整研发仓库。源码提交包的安装与运行使用 `docs/submission/05_运行与复现说明.md`；这里的实验命令不随裁剪后的源码包分发。

本文说明本地安装与启动、开发预览、冻结输入实验复现及视频上传所需的服务配置。命令以 Windows PowerShell 为例，分别在标明的仓库目录中执行。

开发预览和机制实验使用预先构造并冻结的结构化输入，实际执行 PEAD 与协议校验；真实视频分析需要另外配置上游服务。两类运行的结果按各自输入范围解释。

## 一、运行模式与所需条件

### 1.1 三种模式

| 模式 | 是否需要真实模型密钥 | 能验证什么 | 不能验证什么 |
|---|---|---|---|
| 冻结样例开发预览与验证 | 否 | 开发预览检查界面；冻结样例运行检查 PEAD、报告校验、SQLite 保存和 HTML 导出 | 真实视频理解、模型识别准确率 |
| 工程回归/机制验证 | 否 | 18 套 fixture、关系回答穷举、论证攻防、规则与报告边界 | 真实视频上的效果与泛化 |
| 真实视频联调 | 是，且需要配置所有必需服务 | 在给定环境中检查模型回包、输入契约与端到端流程 | 仅凭少数联调样例不能推出准确率或总体效果 |

### 1.2 环境依赖

- Python 3.11 或更高版本；仓库锁定环境已记录 Python 3.11.15 的验证。
- Node.js；仓库现有验证记录使用 Node 24。
- uv，用于按 uv.lock 安装后端依赖。
- FFmpeg 提供的 ffprobe，用于真实视频上传路径的媒体时长读取。
- 支持本地访问的桌面浏览器。
- 若要调用真实模型，另需按实际供应商配置服务端密钥、API 地址和模型标识。

## 二、从干净目录安装

### 2.1 检查工具是否可用

在 PowerShell 中分别执行：

~~~powershell
python --version
node --version
npm --version
uv --version
ffprobe -version
~~~

若 ffprobe 不存在，真实上传路径无法正常读取视频时长。单元测试中的 ffprobe 调用可能被打桩，因此测试通过不代表目标机器的 ffprobe 已安装。

### 2.2 安装后端

在仓库根目录打开 PowerShell：

~~~powershell
Set-Location backend
uv sync --locked --python 3.11
~~~

该命令依据 uv.lock 安装锁定依赖。若环境中没有 uv，可先按项目 README 安装；也可使用系统 Python 执行 pip 安装，但为减少版本漂移，优先使用锁定环境。

Windows 本机运行时可使用虚拟环境解释器：

~~~powershell
.venv/Scripts/python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
~~~

后端默认绑定本机地址 127.0.0.1，不应在未完成认证、权限、部署安全和隐私审查前直接暴露到公网。

### 2.3 安装前端

另开一个 PowerShell 窗口：

~~~powershell
Set-Location frontend
npm ci
Copy-Item .env.example .env.local
npm run dev -- --hostname 127.0.0.1 --port 3000
~~~

浏览器打开 http://127.0.0.1:3000。前端 API 基地址由 NEXT_PUBLIC_API_BASE_URL 配置，默认指向 http://127.0.0.1:8000。若端口或 API 地址与目标环境不同，应同步调整前端环境配置。

不要把模型服务密钥放进 NEXT_PUBLIC_ 开头的前端环境变量；任何暴露给浏览器的变量都不应存放服务端秘密。

## 三、检查后端是否启动成功

浏览器或命令行访问：

~~~powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
~~~

应检查响应是否表明服务健康，并核对 PEAD 求解器与规则集信息。健康接口只能说明服务端基本状态，不代表真实模型 API 已连接或真实视频分析已验证。

若无法访问：
1. 确认后端终端是否仍在运行；
2. 确认 8000 端口没有被其他程序占用；
3. 确认命令是在 backend 目录执行；
4. 检查启动日志中的依赖、规则配置或导入错误；
5. 不要通过关闭协议校验或替换默认规则来绕过启动失败。

## 四、冻结样例开发预览

### 4.1 操作步骤

1. 按第二节启动前端开发服务。
2. 浏览器直接打开 http://127.0.0.1:3000/design-preview。
3. 选择冻结展示案例，查看结论概览、分镜结果、问题与证据、整改与总结。
4. 对照口播、事件归属、证据 ID 和时间范围，检查界面与样例记录是否一致。
5. 需要重新执行 PEAD 和校验时，按第五节运行样例验证命令。

`/design-preview` 仅供开发环境预览，正式首页不设置预设案例入口，生产环境不开放该页面。预览读取已有展示记录，不会因切换案例而重新调用模型或运行审核任务。

### 4.2 五个展示案例

| 案例 | 冻结输入内容 | 主要观察点 |
|---|---|---|
| 天台动作 + 鼓励模仿 | 危险动作与鼓励话语被定义为同一事件 | 危险行为诱导的支持路径与 FLAG |
| 同动作 + 明确劝阻 | 动作不变，口播改为明确警示 | 反向语境影响；不把该策略的 NONE 当作动作安全 |
| 跨事件误关联 | 厨房动作与户外骑行分属不同事件，冻结输入中注入错误关系回答 | 事件作用域约束与 REVIEW |
| 手机屏幕身份证照片 | 屏幕显示证件照片，稍后才提及打码 | 隐私线索的证据定位与整改建议 |
| 柯基宠物日常 | 普通宠物活动，无风险线索 | 干净负例；不无依据地生成风险 |

界面中的静态场景图用于帮助理解案例，不参与裁决。预览未关联原始视频，原片回看不可用；需要回看时，应通过正式上传路径提交获授权的视频。

## 五、运行工程回归和机制检查

所有命令均在 backend 目录执行。

### 5.1 后端自动化测试

~~~powershell
uv run python -m unittest discover -s tests -v
~~~

保存完整控制台输出。记录实际通过、失败、跳过数量与退出状态；不要只把测试命令放进报告而不记录执行结果。

### 5.2 Fixture 数据一致性与期望值

~~~powershell
uv run python -m fixtures.generate --check
uv run python -m fixtures.validate
uv run python -m fixtures.validate --matrix
~~~

第一条检查静态样例是否与源定义一致；第二条将用例送入真实项目校验与离线编排，并核对人工维护的期望值；第三条展示策略/规则覆盖矩阵。若出现漂移，应先判断是源定义、生成产物还是实现行为变化，不要盲目覆盖期望结果。

### 5.3 Prompt 契约检查

~~~powershell
uv run python -m fixtures.prompt_contract
~~~

当前生成报告列出 31 项静态检查通过。最终数字以最终 commit 的新报告为准。此检查不调用模型，不验证模型是否遵循 Prompt。

### 5.4 决策真值表与论证机制

~~~powershell
uv run python -m fixtures.truth_table
uv run python -m fixtures.argumentation_report
uv run python -m fixtures.argumentation_html --check
~~~

检查关系回答组合、论证节点/攻击关系和 HTML 产物是否一致。真值表覆盖当前 fixture 定义的 64 种关系回答组合，不代表所有可能的视频或事件图。

### 5.5 同输入对照

~~~powershell
uv run python -m fixtures.compare_pead --check
~~~

检查已保存的对照输出是否与当前生成结果一致。若需要重新生成报告，先查看脚本参数和当前仓库说明，再执行相应生成命令；生成后再次运行 --check。报告中的 8/10 与 10/10 是预设处置预期符合计数，不是真实视频准确率。

### 5.6 前端检查与构建

在 frontend 目录执行：

~~~powershell
npm ci
npm run lint
npm run build
~~~

当前 package.json 中 lint 脚本执行 TypeScript 严格检查。生产构建是否成功必须以本次运行日志为准，不能只依据此前某台机器的结果。

## 六、真实视频路径与服务配置

真实上传流程依赖 ffprobe 以及配置完成的必需模型服务。仓库 backend/.env.example 中的字段是配置模板，实际名称以当前文件为准。README 当前列出的配置项包括：

- 视频解析：VIDEO_MODEL_API_KEY、VIDEO_MODEL_BASE_URL、VIDEO_PARSE_MODEL；
- 问题定位：ISSUE_LOCATOR_API_KEY、ISSUE_LOCATOR_ENDPOINT、ISSUE_LOCATOR_MODEL；
- 审核报告：AUDIT_REPORT_MODEL（按当前实现可选）；
- 关系核验：RELATION_MODEL_API_KEY、RELATION_MODEL_ENDPOINT、RELATION_MODEL_ID（按当前实现可选）；
- 数据库位置：VIDEOGUARD_DB。

配置真实服务前，应逐项核对适配器支持的接口协议、模型标识、请求限制和数据处理政策。密钥只放在后端环境中，不得提交到仓库、截图、PDF 或浏览器端。

当前上传限制按 README 的记录为 MP4/MOV/WebM、文件不超过 6 MB、时长不超过 3 分钟。具体限制应以最终代码中的校验逻辑为准。若缺少必需密钥或服务调用失败，应检查系统是否显式失败并留下记录，而不是期待它返回一个伪造的审核成功结果。

真实模型联调步骤建议：
1. 使用获授权、无敏感信息的短视频；
2. 先验证健康接口和每个适配器配置；
3. 执行一次端到端上传并保存请求时间、配置版本和脱敏日志；
4. 检查阶段一事实、阶段二线索、阶段三关系回答是否满足 PEAD 上游假设；
5. 执行 fixtures.upstream_assumptions 的假设检查工具；
6. 由人工逐项核对原视频与事实/时间/事件 ID；
7. 只有在形成独立人工标注集后，才开始计算准确率、误报率和召回率。

## 七、报告产物与版本追溯

重要产物包括：

- backend/reports/pead-truth-table.md 与 .json：决策组合结果；
- backend/reports/mock-pead-comparison.md、.json、.csv：同输入对照；
- backend/reports/pead-argumentation.md 与 .html：论证攻防机制；
- backend/reports/prompt-contract.md：Prompt 契约检查；
- backend/reports/pead-self-review-validation.json：特定自查轮次的环境、测试和不变量统计；
- backend/reports/demo-showcase/：离线展示案例、记录与截图包；
- docs/assets/demo/：参赛文档使用的界面截图。

每次定稿应把生成文件对应的 Git commit、执行环境和命令写入验收记录。不要把不同运行轮次的数字合并为一个“总测试数”，也不要用历史日志替代最终提交版本的运行结果。

## 八、常见故障与排查

| 现象 | 优先检查 | 处理原则 |
|---|---|---|
| 后端提示无法使用 ffprobe | PATH、FFmpeg 安装与 ffprobe -version | 修复媒体工具环境后再测试真实上传 |
| uv sync 解析了错误的 pyproject.toml | 当前目录及父目录是否存在同名项目配置 | 在干净父目录克隆，或从 backend 目录启动 |
| 前端无法连接 API | NEXT_PUBLIC_API_BASE_URL、后端端口和服务状态 | 修正本地地址，不把 API Key 放到前端 |
| 冻结样例能运行但视频上传失败 | 必需服务配置、授权、文件类型、大小、时长和模型协议 | 区分环境错误、输入校验失败与模型服务失败 |
| Prompt 契约通过但真实模型回包失败 | 实际回包结构、嵌套字段、枚举和服务协议 | 静态检查不是完整契约证明，应记录回包差异并更新测试 |
| 生成产物与已提交文件不一致 | fixture 源定义、规则配置、版本和生成器 | 检查差异原因，再决定更新源或产物 |
| 规则文件无法加载 | JSON、规则 ID、优先级、必要守卫和规则集版本 | 不删除完整性校验；修正配置并重新跑测试 |
| 现场没有模型服务密钥 | 开发环境 `/design-preview` 和离线报告 | 用冻结记录展示界面与机制；实时分析需要上游服务配置 |

## 九、复现结果应如何报告

一个可复现的记录至少包含：

- Git commit SHA；
- 操作系统、Python、Node 和依赖锁定状态；
- 执行的命令及退出状态；
- 测试通过/失败数量；
- fixture、真值表、对照、论证报告和契约检查是否通过；
- 是否配置真实模型 API，若配置，是否确实发生真实调用；
- 所用视频的授权状态和脱敏方式；
- 尚未完成的检查及其影响。

按实际执行情况记录是否调用上游 API。最终结论覆盖本次确实执行的测试与输入范围。
