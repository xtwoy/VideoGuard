本记录不加入源码提交包，也不作为作品正文提交。

## 一、交付位置

- 压缩包：[VideoGuard-E_源码提交包.zip](../../deliverables/VideoGuard-E_源码提交包.zip)。
- 解压目录：`deliverables/VideoGuard-E-source/`。

## 二、包含与排除

保留正式前端、FastAPI 接口、视频上传、模型适配器、PEAD 引擎及规则、当前策略配置、提示词与协议、数据库与 HTML 报告代码、依赖锁定文件、环境配置样本、第三方说明和启动脚本。

不包含以下研发材料：

- `backend/fixtures/`、冻结样例、Mock 对照与展示输入；
- `/api/demo`、`/api/demo/cases` 接口及其编排入口；
- `frontend/app/design-preview/`、场景配图组件与静态图片；
- 预生成报告、截图、历史数据库、视频和其他运行数据；
- 测试脚本、内部文档、交接记录、Git 历史和 AI 指令文件；
- 实际 `.env`、密钥、虚拟环境、`node_modules` 和构建缓存。

研发仓库中的实验工具与记录继续保留。它们不会因导出而被删除。

## 三、提交副本的必要裁剪

单纯删除 `fixtures` 会导致原 `pipeline.py` 在导入时读取不存在的数据。导出脚本因此同时处理：

1. `main.py`：移除演示依赖与两项演示路由；后端首页指向前端 3000 端口。
2. `pipeline.py`：移除导入即读取的演示常量和 `run_demo`，保留正式编排、校验与报告回退。
3. `database.py`、`report.py`、前端记录类型：只保留 LIVE 运行记录。
4. 前端共享结果组件：去除开发配图的参数、渲染分支与依赖；保留上传视频预览及结果界面。

PEAD 核心、规则配置和模型协议不因导出而改写。导出脚本对转换位置作精确匹配，源结构变化时会报错，不能靠宽泛文本删除继续打包。

## 五、再次导出

在仓库根目录执行：

```powershell
python -X utf8 tools/package_submission.py --replace
```

导出脚本仅依赖 Python 3.11 或以上的标准库。它只重建 `deliverables/VideoGuard-E-source/` 与对应 ZIP、摘要，不修改开发源码。输出目录已加入 `.gitignore`，用于生成交付件，不纳入源码版本记录。

再次验证需先在单独的解压目录安装依赖并构建前端，再使用该目录的 Python 执行：

```powershell
解压目录/backend/.venv/Scripts/python.exe -X utf8 tools/verify_submission.py 解压目录
```

38 项核心回归来自研发仓库现有测试中不依赖展示输入的测试类，仅在验证目录临时使用，不包含在提交压缩包内。
