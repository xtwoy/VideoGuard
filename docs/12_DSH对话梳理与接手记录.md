## 5. 接手发现的材料风险

1. **旧交接指令与最新决定冲突。** `HANDOFF.md` 与 `docs/05` 仍有“不写参赛报告”和优先真实联调的旧要求，已在入口添加更新说明；早期计划保留供追溯。
2. **34/34 不能代表完整契约证明。** `fixtures/prompt_contract.py` 只检查部分字段和枚举；`match_enum()` 接受超集，关系协议版本检查直接标为通过，未执行完整 JSON Schema 与运行时校验器的等价验证。报告/答辩中“以后失败不会是格式契约问题”的推断过强，需要收窄为“已检查的 34 项未发现不一致”。
3. **攻防解释与实际攻击边有矛盾。** 生成器及报告称反向语境论证“没有攻击者”，但输出同时列出 `LOCAL_PROMOTION → COUNTER_CONTEXT`。该场景还有无攻击者的 `RELATION_MISSING`，其攻击 `LOCAL_PROMOTION`，进而防御 `COUNTER_CONTEXT`。应按实际防御链解释，不能说反向论证没有攻击者。
4. **答辩稿对环的概括不成立。** 不能笼统说“偶环不影响可接受性，奇环才会未决”；孤立的相互攻击也可能在 grounded 下均未决，外部攻击与防御决定具体标签。需结合当前图解释。
5. **反证遗漏不保证总能转人工。** 答辩稿 B4 先承认上游漏警示可能误判，随后又说“这类情况会落到 REVIEW”，表述相互冲突。检查输入里没有反证，不能证明原片没有反证；不能承诺所有遗漏都会被识别并复核。

这些是本次阅读确认的收尾项，尚未在业务代码、生成器与答辩稿中修复。检查全绿只能说明现有检查通过，不能消除上述问题。
