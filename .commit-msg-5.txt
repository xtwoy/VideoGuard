fix: 事件证据按时间归属，候选对覆盖可追溯，关系回答需自洽

第五轮审计的入口层问题。核心共性是：PEAD 只能保证"收到的证据如何论证"，不能保证"这条证据确实属于这个事件、这次核验确实覆盖了该问的关系"。

事件证据归属（优先处理）：
- 事件的 evidence_refs 此前只要有一条与事件时间重叠即可，其余可以来自别的场景。上游多填一个事实 id 就能把另一场景的警示拖进本事件，而 PEAD 拿到的事实集合已经错了。现要求每条引用都与事件时间重叠，counter_context_refs 同规则。
- 风险线索此前只校验引用"存在于全视频事实目录"，可以借用其它场景的事实却仍按声明事件参与判断。现要求线索引用落在其所声明事件的时间范围内（event.evidence_refs 是摘要不是穷举，故按时间判定而非集合包含）。

候选对覆盖：
- 旧排序只看时间距离，三条更近的跨事件话语就能占满名额，同事件的真实关系排到第四位；而 semantic_check 仍报 COMPLETE——被问的都答了不等于该问的都问了。
- 改为同事件优先、其次按距离；新增 eligible/selected/omitted 计数；有未提问的合格候选时 semantic_check 记为 PARTIAL_CANDIDATES，导出报告显示关系核验不完整。

关系回答自洽性：
- choice 与 probabilities 此前各自校验、互不比对，choice=encourages_same 而 unrelated 概率 0.97 的回答会被当作可靠结论。现要求所选标签是概率分布的首要选项，否则记 INVALID_RESPONSE / PROBABILITY_CONFLICT 并退回人工复核；四类 choice 均有反例测试。

采集脚本绕过清洗：
- upstream_capture.py 此前把原始解析回包直接交给问题定位服务，跳过 clean_video_parse；context 中的未知字段会原样外发。现保留原始回包用于取证，但第二阶段使用清洗后的对象。回归测试在原始 context 中塞入姓名、电话、地址，断言外发载荷不含该字段。

脱敏边界：
- 补充分隔形式手机号（138-1234-5678、138 1234 5678、+86 138 1234 5678）。银行卡号、姓名、自由文本地址、画面文字仍不覆盖，已在 README 与模块注释中写明"是基本防护，不是匿名化"，并用测试固定已知缺口。

另修复：多个文件因 PowerShell 写入带上了 UTF-8 BOM（会破坏 Python 解析），已全部清除。

验证：后端 214 项测试通过（新增 11 项上游边界回归）；fixtures、Mock 对照、攻防页、prompt 契约四项一致性检查通过；前端类型检查通过。
